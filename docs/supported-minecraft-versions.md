# Нижняя граница поддерживаемых версий Minecraft

**UDMC не может поддерживать Minecraft ниже 1.20.2.** Это не решение, которое можно
пересмотреть настройкой: в игре до 1.20.2 отсутствует механизм, на котором держится
проверка клиента при входе.

## Почему именно 1.20.2

В 1.20.2 Mojang добавил в протокол **фазу configuration** — промежуток между входом игрока
и попаданием в мир, где сервер и клиент обмениваются данными, а сервер может отклонить
игрока с читаемым сообщением. UDMC проверяет там наличие и версию клиентского мода.

Проверено на локальных сборках Minecraft (наличие классов `ServerConfigurationPacketListenerImpl`,
`ConfigurationTask`, `DiscardedPayload`):

| Версия | Классы фазы configuration |
| --- | --- |
| 1.19.4 | нет |
| 1.20.1 | нет |
| 1.20.4 | есть |
| 1.20.6 | есть |
| 1.21.1 | есть |

Граница проходит между 1.20.1 и 1.20.4; в документации Mojang фаза появляется в 1.20.2.

## Почему нельзя вернуться к прежнему способу

До этого UDMC спрашивал клиент в **фазе входа**, через ванильный канал login-запросов.
В версиях ниже 1.20.2 это единственный доступный способ — но он неработоспособен на реальных
сборках, и это измерено, а не предположено:

- Fabric API обрабатывает **каждый** канал фазы входа сам и отменяет ванильный вызов, поэтому
  исход решает случайный порядок применения миксинов. На сборке с Fabric API клиент не получал
  вопрос, и сервер сообщал исправно установленному моду «клиент не установлен».
- Четыре разных обхода были проверены на настоящем стенде, и каждый работал ровно в одной
  конфигурации и ломался в другой: без Fabric API против с ним, на клиенте против на сервере.

В самой игре до 1.20.2 у фазы входа нет никакой поддержки для такой проверки:
`handleCustomQueryPacket` там просто отключает игрока. Именно поэтому Fabric API забрал этот
канал целиком, и именно поэтому все моды с подобной задачей (owo-lib, Fabwork, Polymer)
переехали в фазу configuration, как только она появилась.

## Что это значит на практике

Каталог поддерживаемых целей — `minecraft/agent-catalog.json`. Добавлять туда версию ниже
1.20.2 нельзя: агент соберётся, но проверка клиента работать не будет, а на сборке с
Fabric API — сломается молча, показывая игрокам неверную причину.

Если такая поддержка когда-нибудь понадобится, это отдельная задача со своим механизмом
(например, проверка после входа в игру с последующим отключением), со своими компромиссами
и своим прогоном по матрице конфигураций.

Подробности решения и разбор альтернатив: `docs/client-verification.md`.
