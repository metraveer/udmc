# Расширение совместимости UDMC

Дата исследования: 27 августа 2026. Обновление реализации: 28 августа 2026.

Состояние на 0.27.1: общий код агентов, NeoForge 1.21.1 и каталог сочетаний сделаны (пункты 1–2 порядка реализации); NeoForge для 26.x открыт (пункт 3); Forge и всё ниже 1.20.2 сняты — проверка входа живёт в фазе configuration, которой там нет ([почему](supported-minecraft-versions.md)). Панель не формирует JAR: она отдаёт один и тот же неизменённый файл для сервера и игроков. Результаты и границы испытаний: [отчёт 0.3.0](internal/testing-0.3.0.md).

## Что работает сейчас

В [каталоге агентов](../minecraft/agent-catalog.json) есть Fabric для Minecraft `1.21.1`, `26.1.2` и `26.2` с Loader `0.19.3`, а также NeoForge `1.21.1` с `21.1.248`. Более новый Loader, разрешённый метаданными, не означает автоматически проверенную совместимость.

NeoForge 26.1.2 и NeoForge 26.2 ещё не реализованы. Переход между платформами требует отдельного игрового профиля и проверки всех модов; генератор не преобразует существующую сборку или мир.

## Предлагаемый охват

Поддерживать конкретные сочетания, а не обещать непрерывный диапазон от 1.20.2 до 26.2 со всеми промежуточными выпусками.

| Загрузчик | Целевые версии Minecraft | Действие |
| --- | --- | --- |
| Fabric | 1.21.1, 26.1.2, 26.2 | Сохранить текущие шаблоны, расширять проверенные версии Loader |
| NeoForge | 1.21.1, 26.1.2, 26.2 | 1.21.1 сделан; 26.x добавлять поэтапно |

Это шесть сочетаний игры и загрузчика, из них два новых. Для каждого нужны оба режима агента и проверки реального запуска. Не требуется выпускать все сочетания одновременно.

Обоснование выбора:

- Сохраняем уже используемые Fabric-проекты и охватываем современную ветку 26.x через NeoForge.
- Для 1.21.1 добавляем вторую экосистему модов. Команда NeoForge отмечала широкое распространение этой ветки и отказ от собственной ветки 1.20.1 в пользу существующей экосистемы Forge. Это историческое обоснование, не текущая статистика популярности: [итоги NeoForge за 2024 год](https://neoforged.net/news/2024-retrospection/).

Следующая очередь при необходимости: Fabric и NeoForge для 1.21.11. Сначала закончить игровые испытания основной матрицы.

Не включать в первый этап snapshots, старые 1.12.2/1.16.5 и гибридные серверные платформы. Quilt отложить до отдельной проверки: его Loader продолжает развиваться, хотя QSL, QFAPI и Quilt Kotlin Libraries прекращают развитие для 26.1 и новее. Это не прекращение работы всего Quilt: [объявление команды](https://quiltmc.org/en/blog/2026-02-03-non-obfuscated-updates/).

## Версии загрузчиков

Снимок официальных каталогов на дату исследования, не утверждение совместимости с UDMC:

| Загрузчик и Minecraft | Найденные версии | Как использовать при переносе |
| --- | --- | --- |
| Fabric, текущие три профиля | 0.19.3 с `stable: true`; 0.19.4 с `stable: false` | Сохранить 0.19.3 как текущую базу, отдельно проверить 0.19.4 |
| NeoForge 1.21.1 | 21.1.248 | Кандидат для первого порта |
| NeoForge 26.1.2 | 26.1.2.99 | Кандидат для этого профиля |
| NeoForge 26.2 | 26.2.0.69 | Кандидат для этого профиля |

Источники значений: [Fabric Meta](https://meta.fabricmc.net/v2/versions/loader), [NeoForge Maven](https://maven.neoforged.net/releases/net/neoforged/neoforge/maven-metadata.xml). У NeoForge выбраны последние версии соответствующих веток без суффикса предварительного выпуска. Метка Fabric `stable: false` сама по себе не доказывает, что выпуск является beta: такое значение есть и у предыдущих релизов.

Политика UDMC:

1. Разделить в каталоге версию сборки агента, рекомендуемый Loader, допустимое ограничение версии и список фактически проверенных выпусков. Сегодня одно поле `loaderVersion` смешивает эти понятия.
2. Для нового проекта автоматически выбирать проверенную рекомендуемую версию. Другие проверенные варианты показывать списком, без ручного ввода произвольных чисел.
3. Не включать новый upstream-релиз автоматически только потому, что он появился в API. Каталог доступных вариантов поставлять с проверенными шаблонами UDMC.
4. Для уже подключённого сервера брать фактический загрузчик и версию из агента. Смена значения в генераторе не должна менять платформу существующей сборки.
5. Не обещать поддержку всего диапазона `21.x`: версия Minecraft, метаданные агента и испытания должны совпадать. Для выбора версии достаточно повторно использовать один JAR, если его совместимость подтверждена; отдельный JAR на каждый patch не обязателен.
6. Учитывать исправления безопасности, а не только метку recommended. Например, NeoForge исправил сетевую уязвимость в 1.21.1 начиная с 21.1.229 и в 26.1.2 начиная с 26.1.2.44-beta: [объявление об исправлении](https://neoforged.net/news/mitigating-vulnerabilities-network/). Это исправление конкретной уязвимости, а не гарантия безопасности всех последующих версий.

## Что потребуется изменить

Это перенос агента и проверок модов, а не добавление пунктов в выпадающий список.

| Участок текущего кода | Необходимая работа |
| --- | --- |
| `minecraft/udmc-sync-fabric` | Сделано в 0.3.0: общие операции живут в `udmc-sync-common`, платформенные адаптеры запуска, путей, игровых экранов, статистики и команд остались у каждого загрузчика |
| `ModMetadata.java`, `AgentFiles.java`, `ClientModCheck.java` | Сделано в 0.3.0: разбор NeoForge, правила зависимостей, несколько модов в JAR, вложенные зависимости, обнаружение агента и конфликты личных файлов |
| `scripts/build-minecraft-fabric.js` | Сделано в 0.3.0: собирает каждый вариант каталога своим Gradle-проектом; игра, Loader и Java берутся из `agent-catalog.json` |
| `src-tauri/build.rs`, `src-tauri/src/generator.rs` | Сделано иначе: панель отдаёт один и тот же неизменённый JAR, ролей и настроек внутри файла нет |
| `ui/assets/generator-ui.js`, `protected-settings.js` | Выбирать шаблон по загрузчику и Minecraft, сохранить защиту чувствительных настроек и старые Fabric-проекты |
| `ui/assets/file-intake.js`, `modrinth*.js` | Определять метаданные соответствующего загрузчика, фильтровать каталог и обязательные зависимости под фактическую платформу |
| Страница компонентов, документация, тесты | Добавить нужные Java и загрузчики, проверять установщик и каждый встроенный шаблон |

Пути `src-tauri` и `ui` в таблице относятся к `apps/admin-desktop/`.

Для NeoForge нужен настоящий TOML-парсер и соответствующие правила диапазонов версий (есть). Fabric использует `fabric.mod.json`; NeoForge — `META-INF/neoforge.mods.toml`. Поле `loaderVersion` в NeoForge TOML обозначает версию языкового загрузчика FML, а не номер NeoForge. Сторона установки не всегда однозначно определяется метаданными: при неопределённости нельзя молча отправлять мод обеим сторонам. См. [метаданные NeoForge](https://docs.neoforged.net/docs/gettingstarted/modfiles/).

Не нужно переписывать Windows-приложение или делать лаунчер. Оно содержит готовые JAR и отдаёт один и тот же неизменённый файл для сервера и игроков. Администратору не нужны Gradle, Rust или JDK.

## Java и игровые API

| Minecraft в плане | Java для игрового профиля |
| --- | --- |
| 1.21.1 | 21 |
| 26.1.2, 26.2 | 25 |

Основание: [NeoForge 1.21.1](https://docs.neoforged.net/docs/1.21.1/gettingstarted/), [переход Minecraft 26.1 на Java 25](https://docs.neoforged.net/primer/docs/26.1/).

Minecraft ниже 1.20.2 не поддерживается и поддержан быть не может: [supported-minecraft-versions.md](supported-minecraft-versions.md).

Меняются и игровые API. Например, в 26.2 изменилось расположение методов управления экранами: [заметки Fabric о переносе](https://fabricmc.net/2026/06/15/262.html). Поэтому один универсальный JAR для всех версий не является целью.

## Порядок реализации

1. Сделано: каталог сочетаний и адаптеры, поведение трёх Fabric-сборок сохранено.
2. Сделано: NeoForge 1.21.1 целиком — сервер, клиент, метаданные, каталоги, публикация и удаление, проверка на изолированном игровом стенде.
3. Перенести адаптер NeoForge на 26.1.2 и 26.2, отдельно проверив игровые API и клиентские экраны.
4. После испытаний включать готовые сочетания в поставляемый каталог. Затем рассматривать дополнительные версии Minecraft.

## Критерии готовности

- JAR запускаются на настоящем выделенном сервере и клиенте каждой заявленной пары Minecraft/Loader, а не только компилируются.
- Неверная игра, Loader или Java дают понятную ошибку без изменения файлов. Клиентский код не загружается на dedicated server.
- Добавление, обновление и удаление проверены с реальными модами, обязательными зависимостями и разными сторонами установки.
- Личные моды, изменённые конфиги и моды агента не удаляются без предусмотренного согласия; конфликт показывает точный список файлов.
- Сохраняются проверка подписи и хеша, разграничение администраторов, отказ от старого manifest и восстановление после обрабатываемых ошибок.
- Проверены перезапуск, занятые JAR на Windows, прерванная загрузка, RCON, команды и статистика. Есть испытания клиента и сервера на поддерживаемых ОС.
- В файле мода нет ни ключей, ни адресов; проект создаётся на сервере и восстанавливается из резервной копии при привязке.
- Панель и каталоги не предлагают неподдерживаемые сочетания.

Поддержка разных загрузчиков означает выбор платформы проекта. Она не превращает Fabric-моды в Forge-моды, не гарантирует вход Forge-клиента на Fabric-сервер и не переносит мир между платформами. Такие миграции требуют отдельной проверки модов и резервной копии мира.
