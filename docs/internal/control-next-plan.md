## Исходное состояние

Windows Tauri Control 0.3.0, Fabric 1.21.1 / 26.1.2 / 26.2 и NeoForge 1.21.1. Не лаунчер. Текущее приложение умеет черновики, публикацию, удаление управляемых файлов, Modrinth, RCON, приглашения администраторов. Не путать существующий API с удобством и полнотой пользовательского сценария.

## Требования и приёмка

1. **Раздача клиентского агента и проверка входа.** Администратор вручную ставит только серверный JAR. После подключения Control автоматически передаёт соответствующий безопасный клиентский JAR. Сервер раздаёт его по ссылке с инструкцией. Настройка: требовать агент или пускать с предупреждением. Проверка должна работать до допуска в игру, когда это позволяет загрузчик. Не обещать запись JAR из немодифицированного клиента и не публиковать серверные секреты.
2. **Обновление самих агентов.** Кнопка рядом с генерацией JAR. Обновлять установленный серверный агент и публикуемый клиентский агент; уже установленные клиенты получают обновление. Проверять подпись, платформу и хеши, сохранять ключи/ID/настройки, применять занятые JAR только после завершения игры/сервера. Нужны резервная копия, состояние операции и восстановление после сбоя.
3. **Понятное завершение синхронизации в Minecraft.** После успеха предлагать сетевую игру и, при известном игровом адресе, подключение к серверу. При изменённых модах сначала обязательный перезапуск. Повторная проверка уместна при ошибке, не как единственное основное действие после успеха.
4. **Назначение модов из каталога.** Автоматически определять клиент/сервер/оба из достоверных метаданных, показывать допустимые варианты и объяснение опциональности. Не угадывать при неизвестных данных. Сохранять объяснение и происхождение в черновике.
5. **Выбор мода и отмена.** Версия, зависимости и действия рядом с выбранным модом, не в конце длинного списка. Явная отмена выбора/подготовки; не обещать отмену уже принятой сервером мутации. Ошибка или отмена не должны оставлять интерфейс в занятом состоянии.
6. **Полный UI/UX.** Чёткие области ответственности, удобная навигация, предсказуемые действия, адаптация к размеру окна, доступность клавиатурой, без наложения/сжатия текста. Нативная Windows-проверка, не только DOM.
7. **Удаление и существующие файлы.** Понятно объяснить принятие файла под управление. Из панели удалять серверные и управляемые клиентские файлы через проверяемую публикацию. Для неуправляемого серверного файла отдельное явное действие с хешем/резервной копией и проверкой зависимостей. Не удалять произвольные личные файлы игроков.
8. **Разделение сборки на вкладки.** Отдельные представления черновика, опубликованного состава и файлов на сервере. Счётчики и общая видимость неопубликованных изменений; не требовать длинной прокрутки до инвентаризации.
9. **Помощь по совместимости.** До публикации проверять состав и серверный инвентарь, показывать конкретные отсутствующие/неподходящие зависимости, дубликаты, стороны и допустимые исправления. Учитывать вложенные моды. Не гарантировать безопасность мира по одним метаданным.
10. **Другие источники модов.** Изучить официальные открытые API, лицензии, необходимость ключей и ограничения раздачи. Добавлять только реально доступный проверяемый источник; без обхода запретов и скрытых ключей. Объяснить ограничения, если интеграция требует регистрации/разрешения поставщика.
11. **Английский и русский языки.** Полный перевод интерфейса и пользовательских сообщений, переключатель языка, первый выбор по системе, явный выбор сохраняется. Проверить длинные строки и динамические состояния. Язык не должен сбрасываться при смене сервера.
12. **Богатый каталог.** Полное описание, изображения и сведения о проекте. При подключении фильтры автоматически соответствуют серверу. Зависимости проверяются именно для выбранной игры/загрузчика; несовместимость объясняется. Не разрешать молча устанавливать заведомо неполный обязательный набор. Решение об экспериментальных установках требует отдельного явного дизайна и не должно отключать защиту публикации.
13. **Несколько серверов.** Переключатель проектов/подключений внизу слева, добавление и настройка в модальном окне. В одном месте подключение, генерация агентов и связанные параметры. Раздельные учётные данные, ключи, черновики интерфейса, RCON и история; быстрый переход, отмена устаревших запросов, миграция прежнего единственного подключения без потерь. В UI называть сущность сервером/проектом, а не аккаунтом Minecraft.
14. **Совместная работа администраторов.** Актуальные изменения между панелями, защита всех мутаций от устаревших данных, не только публикации. Для конфликтующих операций блокировка с владельцем, сроком действия и освобождением после сбоя. Понятная плашка с именем администратора, тесты двух независимых клиентов и отзыва доступа.

## Порядок реализации

1. Аудит кода, протоколов и источников; определить безопасные границы обновления агентов и входа.
2. Серверные контракты для агентов, проверки состава и совместного редактирования, миграции и тесты.
3. Серверные профили и локализация, новая навигация/модальные настройки.
4. Каталог, назначение, подсказки, просмотр/удаление и разделение сборки.
5. Игровые экраны, доставка/обновление агентов, проверки загрузчиков.
6. Полные тесты, нативные и игровые проверки, документация и установщик.

## Принятые технические решения

- `AdminWorkspace` живёт под блокировкой `ManifestStore`. Ревизия содержит случайную эпоху процесса + счётчик; перезапуск инвалидирует старые панели. Сервер возвращает 428 без протокола, 409 для устаревшей ревизии, 423 при чужой аренде. Старым Control потребуется обновление для записи, чтение остаётся доступным.
- Долгая загрузка не держит блокировку хранилища. Перед фиксацией повторно проверяются доступ, аренда и ревизия. Неизвестный результат не повторяется автоматически.
- `Manifest.serverRemovals` хранится только в черновике и очищается в опубликованном манифесте. Файлы вне управления удаляются с проверкой точного SHA-256, метаданных зависимостей и резервной копией `udmc-sync/publish-backup-*`. Личные клиентские файлы не затрагиваются.
- Modrinth: официальная документация описывает version.environment как строку, project.environment как массив разных сред версий; нельзя считать смешанный массив достоверной стороной одной версии. Сохраняем стабильный API v2 и fallback client_side/server_side. Источники: https://docs.modrinth.com/api/operations/getproject/ ; https://docs.modrinth.com/api/operations/getversion/ ; https://modrinth.com/news/article/new-environments/ .
- CurseForge требует выдаваемый поставщиком API key, имеет allowModDistribution; нет основания вшивать чужой ключ или обходить запрет. Источник: https://docs.curseforge.com/rest-api/ . Интеграция ещё не реализована; вопрос не считать закрытым.
- Агент: Control экспортирует только первый серверный JAR. `/admin/agents` отдаёт строго публичные настройки клиента; Tauri собирает клиент из встроенного шаблона без восстановления закрытого ключа. `/admin/agents/client` и `/admin/agents/update` защищены общей ревизией/арендой. Публичные `/agents/client`, `/agents/download`, `/agents/files/<sha256>.jar`, `/agents/install` не раздают серверный JAR.
- Обновлятор `AgentUpdateHelper` использует только JDK, запускается из копии уже установленного агента. Задание содержит подписанный Ed25519 descriptor (Properties), точный старый/новый хеш, PID и время запуска родительской JVM. После её выхода заменяется только один JAR внутри mods; сохраняется `udmc-sync/agent-update/previous.jar`. Wrapper вызывает `--finish`, чтобы не запустить сервер раньше окончания замены. Внешним supervisor нужен такой же шаг/пауза. Автоматически откатить ошибку игрового кода нового агента без контроля над внешним запускатором нельзя: резервная копия предназначена и для ручного восстановления.
- Уже установленная старая 0.3.0 не умеет этот протокол: первый переход серверного и клиентского агента на новый механизм потребует ручной замены. Дальнейшие версии смогут обновляться удалённо. Не обещать ретроактивное обновление старых клиентов.
- Handshake использует отдельный vanilla login query `udmc_sync:login` до допуска в мир. Сверяется проект/протокол/хеш установленного агента. Это проверка нормального клиента, не защита от специально подделанного клиента. Различия Identifier/ResourceLocation изолированы в `src/network/modern|classic`. Никаких дополнительных Fabric API JAR от игроков не требуется.
