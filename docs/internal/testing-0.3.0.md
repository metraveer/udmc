Общие Java-наборы: `storeTest`, `securityTest`, `modCheckTest`, `accessTest`, `httpTest`. Проверяются подписи, номер публикации, отказ от manifest другой игры или загрузчика, роли администраторов, публикация и удаление, сохранность личных файлов, откат при обрабатываемой ошибке записи. Потоковая передача 96 МиБ проверена при heap 64 МиБ.

NeoForge-проверки покрывают TOML, Maven-диапазоны, отдельную версию FML, типы и стороны зависимостей, порядок загрузки, несколько модов в одном JAR, Jar-in-Jar и конфликтующие встроенные версии. DOM-тесты проверяют выбор NeoForge, совместимость при одинаковом номере Minecraft, сохранение выбора, старые Fabric-настройки, Modrinth и обязательный выбор назначения ручного JAR.

## Нативная панель

В отдельном debug-профиле WebView2 проверены окно 940 x 660, редактор совместимости, выбор NeoForge 1.21.1 / 21.1.248, применение и восстановление после перезапуска на 0.3.0. Поля после сохранения заблокированы. Каталог получил настоящие результаты Modrinth для Fabric и NeoForge, не требуя подключённого игрового клиента. Формы и список помещаются в окно; правый контент прокручивается отдельно от сайдбара.

Рабочие ключи, установленное приложение и настройки пользователя не использовались. Проверка интерактивной установки/обновления NSIS в чистой Windows VM в этом выпуске не выполнялась.

## Игровой стенд NeoForge

NeoForge 21.1.248, Minecraft 1.21.1, JDK 21.0.10. В ModDevGradle отключено подключение development source set UDMC; загружались именно `udmc-sync-server.jar` и `udmc-sync-client.jar`, созданные Rust-генератором. Финальный цикл выполнен с агентами 0.3.0.

1. Dedicated server загрузил серверный JAR, создал отдельный тестовый мир и запустил UDMC API. Клиентские классы не вызвали ошибки загрузки на сервере.
2. API вернул тип `neoforge`, фактические версии, TPS, память и справочник из 92 команд. Команда `stop` корректно завершила сервер с сохранением тестового мира.
3. Через API добавлен и опубликован `config/udmc-runtime-check.json` с назначением `both`. Файл появился на сервере.
4. Клиент принял подписанную публикацию: `downloaded=1`, `removed=0`. Файл появился в отдельном клиентском профиле; экран UDMC показал результат и кнопку закрытия Minecraft.
5. Файл удалён из черновика и опубликован повторно. Он исчез с сервера; после запуска клиента получено `downloaded=0`, `removed=1`. Файла больше нет у клиента, а состояние содержит `releaseSequence: 2` и пустой список управляемых файлов.
6. Клиент и сервер штатно остановлены после проверки.

Игровой и HTTP-порты слушали только `127.0.0.1`. Использовались отдельные ключи и каталоги `.qa`, не рабочие миры. ModDevGradle запускает dev-сервер без обычного первого запуска установщика; файл `eula.txt` не создавался и согласие от имени пользователя не записывалось.

## Что ещё не проверено

- Обычная установка NeoForge через официальный установщик и запуск вне ModDevGradle, Linux-хостинг и HTTPS reverse proxy.
- Вход настоящих авторизованных игроков, длительная работа и большие сторонние модпаки. Игровой цикл установки/удаления использовал конфигурационный файл; JAR, зависимости и личные конфликты покрыты отдельными автоматическими тестами.
- Повторные игровые прогоны всех Fabric-профилей после извлечения общего кода. Их сборки и общие автоматические тесты пройдены.
- Произвольные сторонние языковые загрузчики NeoForge, дополнительные аппаратные требования модов и безопасность содержимого мира.
- NeoForge 26.1.2 / 26.2 и Forge 1.20.1: пока не реализованы и не предлагаются генератором.

Не направляйте первый тест на рабочий мир. Сделайте резервную копию и проверьте свой набор на отдельной установке. Ограничения занятых JAR в Windows и внешнего перезапуска остаются: [установка](../installation.md), [план совместимости](../compatibility-roadmap.md).
