# Что чем проверяется

Карта проверок: что каждый слой ловит, чего он не ловит, и что запускать в зависимости от
того, что вы тронули. Она нужна не для полноты, а ради одного правила, которое стоило двух
выпусков: **проверка, которая может молча перестать проверять, хуже, чем её отсутствие** —
её считают покрытием.

## Что запускать

| Что тронули | Что запустить |
| --- | --- |
| Панель: разметка, стили, JS, Rust | `npm test`, `cargo test`, и обязательно снимок экрана через CDP |
| Мод, но не путь игрока | `npm run minecraft:build` — внутри него `gradle check` всех четырёх сборок |
| **Путь игрока**: вход, согласие на проект, синхронизация | всё выше **и** `npm run e2e:login -- 1.21.1`, **и** `npm run e2e:login -- 1.21.1 fabric-api` |
| Протокол входа: каналы, поля, номера | всё выше **и** ручная матрица из [client-verification.md](client-verification.md) |
| Версии, имена файлов, тексты в двух местах | `npm test` — этим занимается `consistency.test.js` |

## Слои

**Node, `npm test`.** Панель целиком в jsdom: экраны, диалоги, ошибки сети, права, языки.
Плюс три проверки, которые смотрят не на панель:

- `i18n.test.js` — каждая строка интерфейса переведена на оба языка, и ни один атрибут не
  остался русским в английской сборке;
- `mod-metadata.test.js` — мод не врёт о себе: лицензия совпадает с `LICENSE`, оба загрузчика
  описывают его одинаково, иконка на месте;
- `consistency.test.js` — то, что записано дважды, совпадает: каталог версий против всей
  документации и страницы компонентов, `classic` против `modern` payload'ов, форма
  замороженного вопроса, имя файла мода у обоих, кто его выдаёт.

**Java, `gradle check` внутри `npm run minecraft:build`.** Прогоняется на всех четырёх
сборках каталога: хранилище и публикация, доступ и приглашения, HTTP, рабочее пространство,
самообновление агента, локализация, проверка модов, решения клиента о проекте и **все вердикты
входа** — включая «установлен, но не приписан», с которого начинает каждый новый игрок. Там же
две проверки из-за одного и того же сервера: своя версия мода у игрока подменяет версию сборки,
если устраивает все моды сборки и даёт всё, что даёт файл сборки, — и игроку об этом говорят;
а мод на сервере, который кладёт записи в реестры и не выдаётся игрокам, называется панелью по
файлу — без игры, через подставленный отчёт о реестрах.

**Rust, `cargo test`.** Генератор (мод отдаётся байт в байт, проект внутрь не попадает), RCON,
защищённые настройки, единственный экземпляр приложения.

**Сквозной вход, `npm run e2e:login -- 1.21.1`.** Поднимает настоящий сервер Minecraft с тем
самым файлом, который ставят игроки, привязывает его так же, как это делает панель, и заходит
протокольным клиентом девять раз: шесть неверных клиентов должны быть развёрнуты с правильной
причиной, верный — войти, а с выключенным правилом те же неверные должны войти и получить
объяснение в чат. Проверяется и порядок: предложение проекта приходит раньше вопроса, а
отказ — раньше, чем игра успела отправить хоть одну запись реестра. Второе — главное: игрок,
у которого ещё нет модов сервера, иначе вылетает по реестрам до того, как UDMC вообще заговорил,
и не может принять проект, который дал бы ему эти моды. Тот же порядок на всех четырёх сборках,
включая 26.x, проверяет `AgentUpdateTest` без стенда.

Второй запуск, `npm run e2e:login -- 1.21.1 fabric-api`, ставит на сервер весь Fabric API, а
клиенту не даёт ничего сверх мода. Это конфигурация, которую новый игрок встречает на настоящем
сервере, и та, где Fabric API прогоняет очередь задач configuration своим циклом раньше игры.
Каждая прежняя попытка проверки входа работала ровно в одной из двух конфигураций, поэтому в
CI гоняются обе.

Формат провода эта проверка не знает наизусть. `scripts/test-support/mod-protocol.js` читает
номера, имена каналов и порядок полей из исходников самого агента. Так сделано намеренно:
прежняя версия этой проверки говорила на канале фазы входа, проверка переехала в фазу
configuration, и проверка не сломалась — она просто перестала что-либо значить и два выпуска
считалась покрытием.

**Ручной стенд, [end-to-end-stand.md](end-to-end-stand.md).** Настоящий клиент с окном. Умеет
оба загрузчика: `npm run e2e:stand -- 1.21.1 neoforge` поднимает NeoForge, у которого своя ветка
проверки — configuration task вместо тика, — и без неё эта ветка не проверялась вовсе.

## Чего автоматика не покрывает

- **Minecraft 26.1.2 и 26.2 на уровне протокола.** `minecraft-protocol` их не знает, поэтому
  сквозной вход гоняется на 1.21.1. Код общий, но кодеки `modern` payload'ов там не
  участвуют — их держит сверка `classic`/`modern` в `consistency.test.js`.
- **Сервер с модами-контентом и клиент только с UDMC.** В матрице нет мода, который добавлял бы
  записи в реестры, поэтому отказ Fabric API «этому серверу нужен Fabric API» и то, как клиент
  заявляет канал синхронизации реестров вместо него, проверяются только на ручном стенде 26.2 с Xaero на
  сервере. Имена каналов записаны в `AgentLoginProtocol.REGISTRY_SYNC_CHANNELS` и меняются только с
  новой веткой Fabric API — сверять с его классами `RegistrySyncPayload` и `DirectRegistryPacketHandler`.
- **Экраны клиента**: согласие на проект, отказ, конфликты файлов. Нужен настоящий клиент.
  Частично закрыто проверками исходника в `i18n.test.js` — это подпорка, а не тест.
- **Порядок миксинов с Fabric API и без него.** Четыре прежние попытки чинить проверку входа
  работали ровно в одной конфигурации; матрицу проходят руками.
- **Вёрстка панели.** Программные проверки регулярно пропускают наложения и лишние линии.
  Снимок экрана обязателен для любой правки вёрстки.

## Правила

1. **Факт, записанный дважды, попадает в `consistency.test.js`.** Версия, имя файла, номер
   протокола, название вкладки в документации — если это можно изменить в одном месте и
   забыть в другом, это должно падать.
2. **Проверка не переписывает то, что проверяет.** Если она знает формат наизусть, она
   переживёт его изменение и промолчит. Читайте формат из источника.
3. **Разбор, который ничего не нашёл, падает вслух.** Пустой результат не должен выглядеть
   как успешная проверка.
4. **Правка на пути игрока — это `e2e:login`, а не «тесты зелёные».** Все ошибки, из-за
   которых игроки не могли зайти, жили именно там, куда не доставал ни один прежний тест.
