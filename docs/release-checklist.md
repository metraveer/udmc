# Как выпускать версии

Короткая шпаргалка. Все команды — в **PowerShell** из корня репозитория.

## Порядок

```powershell
npm run release:build -- patch     # исправления (0.27.1 → 0.27.2)
# или
npm run release:build -- minor     # новые возможности или изменившиеся агенты (0.27.1 → 0.28.0)
```

Команда поднимает номер версии везде, где он записан, прогоняет тесты, собирает мод и
установщик. Дальше:

1. Раздел новой версии в [CHANGELOG.md](../CHANGELOG.md) — до тега: его текст идёт в описание
   релиза.
2. Коммит, пуш и тег:
   ```powershell
   git add -A
   git commit -m "UDMC 0.28.0: коротко о главном"
   git push
   git tag v0.28.0
   git push origin v0.28.0
   ```
3. Тег запускает сборку на GitHub, ждать ~15 минут: https://github.com/metraveer/udmc/actions.
   Тег обязан совпадать с версией в `package.json`, иначе сборка остановится на первом шаге.
   Ту же сборку можно запустить вручную: **Run workflow** с указанием тега.
4. В https://github.com/metraveer/udmc/releases появится черновик с тремя файлами: `.exe`,
   `.exe.sig` и `latest.json`. Опубликуйте его: **Edit** → описание из CHANGELOG →
   **Publish release**. То же можно сделать через API GitHub.

Пока черновик не опубликован, установленные приложения обновления не видят.

### Когда patch, когда minor

| Что изменилось | Команда |
| --- | --- |
| Исправлены ошибки, поправлены тексты | `patch` |
| Появились новые возможности или изменились агенты | `minor` |

Если менялись агенты, об этом сказано в CHANGELOG — тогда в описании релиза стоит упомянуть,
что администраторам нужно нажать «Обновить и перезапустить».

### Ключ подписи

Сборка на GitHub подписывает установщик ключом из секрета `TAURI_SIGNING_PRIVATE_KEY`
(настройки репозитория → Secrets → Actions). Ключ создан без пароля, поэтому второй секрет с
паролем не нужен. Сам ключ лежит в `%USERPROFILE%\.udmc\updater.key` — **держите его резервную
копию** (менеджер паролей, флешка): из GitHub его не прочитать, а без него установленные
приложения не примут ни одного следующего обновления.

## Что происходит у пользователей

- **Приложение**: при запуске показывает плашку «Доступна версия…», обновляется одной кнопкой и перезапускается само.
- **Агенты на сервере**: администратор нажимает «Обновить и перезапустить» в разделе «Агенты и игроки».
- **Игроки**: ничего не делают, их мод обновляется при следующем запуске игры.

## Если что-то пошло не так

| Симптом | Что делать |
| --- | --- |
| Сборка упала (красный крестик в Actions) | Откройте запуск → раскройте красный шаг → там причина. Первый шаг падает, если тег не совпал с версией в `package.json`. |
| В релизе нет `.sig` и `latest.json` | Пропал секрет `TAURI_SIGNING_PRIVATE_KEY`. Добавьте и повторите: `git tag -d v0.28.0; git push origin :v0.28.0; git tag v0.28.0; git push origin v0.28.0` |
| Плашка обновления не появляется | Релиз остался черновиком — его нужно опубликовать (**Publish release**). |
| Тег поставлен с ошибкой | Удалить: `git tag -d v0.28.0` и `git push origin :v0.28.0`, затем поставить заново. |
