# Что делать дальше и как выпускать версии

Короткая шпаргалка. Все команды — в **PowerShell** из папки `H:\UDMC` (приглашение выглядит как `PS H:\UDMC>`).

## Где мы сейчас

| Готово | Осталось |
| --- | --- |
| Репозиторий https://github.com/metraveer/udmc создан и публичный | Добавить ключ подписи в секреты |
| Код отправлен, README со скриншотами на месте | Выпустить первый релиз |
| Описание и темы для поиска заполнены | |
| Приложение знает адрес обновлений | |

## Шаг 1. Ключ подписи (один раз)

Без него сборка релиза упадёт, и обновления не заработают.

1. Скопируйте ключ в буфер:
   ```powershell
   Get-Content "$env:USERPROFILE\.udmc\updater.key" | Set-Clipboard
   ```
2. Откройте https://github.com/metraveer/udmc/settings/secrets/actions/new
3. **Name**: `TAURI_SIGNING_PRIVATE_KEY` → **Secret**: вставьте (`Ctrl+V`) → **Add secret**

Нужен только этот один секрет. Ключ проекта создан без пароля, поэтому секрет `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` не требуется — если вы его уже создали, его можно удалить, сборка его не читает.

Проверить, что получилось: на https://github.com/metraveer/udmc/settings/secrets/actions должна быть строка `TAURI_SIGNING_PRIVATE_KEY`.

**Сделайте резервную копию файла** `%USERPROFILE%\.udmc\updater.key` (менеджер паролей, флешка). Обратно из GitHub его не прочитать.

## Шаг 2. Первый релиз

```powershell
git tag v0.15.1
git push origin v0.15.1
```

Дальше:

1. Следите за сборкой: https://github.com/metraveer/udmc/actions — ждать ~15 минут.
2. Когда закончится, откройте https://github.com/metraveer/udmc/releases — там будет черновик (**Draft**).
3. Проверьте, что внутри три файла: `.exe`, `.exe.sig` и `latest.json`.
4. Нажмите **Edit** (карандаш) → впишите описание (скопируйте раздел версии из [CHANGELOG.md](../CHANGELOG.md)) → **Publish release**.

Готово. Кнопка «Скачать» в README заработает, а установленные копии начнут видеть обновления.

## Как выпускать версии дальше

Обычный порядок: сначала мы вносим изменения, потом вы делаете четыре шага.

```powershell
npm run release:build -- patch     # мелкие исправления (0.15.1 → 0.15.2)
# или
npm run release:build -- minor     # новые возможности (0.15.1 → 0.16.0)

git add -A
git commit -m "UDMC 0.16.0"
git push
git tag v0.16.0
git push origin v0.16.0
```

Затем зайдите в **Releases**, откройте черновик и нажмите **Publish release**.

> Номер в команде `git tag` должен совпадать с версией, которую показала сборка. Посмотреть текущую: `node -e "console.log(require('./package.json').version)"`.

### Когда patch, когда minor

| Что изменилось | Команда |
| --- | --- |
| Исправлены ошибки, поправлены тексты | `patch` |
| Появились новые возможности или изменились агенты | `minor` |

Если менялись агенты, об этом будет сказано в CHANGELOG — тогда в описании релиза стоит упомянуть, что администраторам нужно нажать «Обновить и перезапустить».

## Что происходит у пользователей

- **Приложение**: при запуске показывает плашку «Доступна версия…», обновляется одной кнопкой и перезапускается само.
- **Агенты на сервере**: администратор нажимает «Обновить и перезапустить» в разделе «Агенты и игроки».
- **Игроки**: ничего не делают, их мод обновляется при следующем запуске игры.

## Если что-то пошло не так

| Симптом | Что делать |
| --- | --- |
| Сборка упала (красный крестик в Actions) | Откройте запуск → раскройте красный шаг → там причина. Чаще всего не добавлен секрет из шага 1. |
| В релизе нет `.sig` и `latest.json` | Не добавлен `TAURI_SIGNING_PRIVATE_KEY`. Добавьте и повторите: `git tag -d v0.16.0; git push origin :v0.16.0; git tag v0.16.0; git push origin v0.16.0` |
| Плашка обновления не появляется | Релиз остался черновиком — его нужно опубликовать (**Publish release**). |
| Тег поставлен с ошибкой | Удалить: `git tag -d v0.16.0` и `git push origin :v0.16.0`, затем поставить заново. |
