# Архитектура

## Компоненты

### UDMC Control

Tauri-приложение для Windows. Оно не ищет папку Minecraft и не запускает игру. Основное управление работает через HTTP API серверного агента, а дополнительный RCON-клиент подключается напрямую по TCP:

- меняет название и публикуемую версию сборки;
- загружает и удаляет файлы;
- назначает сторону `client`, `server` или `both`;
- показывает состояние сервера и игроков;
- выполняет команды через Agent API или RCON;
- запрашивает остановку и перезапуск сервера.
- собирает подключение, привязку и выдачу файла в разделе «Настройка сервера», показывает заявки и устройства владельцу;
- просматривает Modrinth без игрового клиента, добавляет выбранные моды в общий серверный черновик.

### Server Agent

`udmc-sync-server.jar`, сформированный Control из встроенного шаблона и приватной конфигурации:

- знает серверный `gameDir`;
- поднимает HTTP API;
- хранит content-addressed blobs;
- хранит опубликованный manifest отдельно от черновика;
- применяет `server` и `both` файлы в `gameDir` только при публикации;
- удаляет управляемый серверный файл только при совпадении SHA-256;
- раздаёт manifest и blobs клиентам.
- получает фактические версии Minecraft и загрузчика;
- отдаёт TPS, tick time, память, uptime, игроков и параметры RCON;
- выполняет команды с правами серверной консоли;
- создаёт маркер перезапуска и корректно останавливает сервер.

### Client Agent

`udmc-sync-client.jar`, сформированный Control без секретов администратора:

- получает текущий `gameDir` от загрузчика;
- скачивает `client` и `both` файлы;
- проверяет SHA-256 перед записью;
- проверяет Ed25519-подпись manifest закреплённым публичным ключом и номер публикации;
- скачивает и проверяет весь набор до применения изменений;
- ведёт собственное состояние управляемых файлов;
- не удаляет локально изменённый файл.

## Поток обновления

```text
Администратор
  -> UDMC Control
  -> POST /admin/files
  -> сервер сохраняет blob и обновляет draft manifest
  -> POST /admin/publish
  -> проверка blobs и временные копии изменяемых серверных файлов
  -> применение серверной разницы и запись опубликованного manifest
  -> клиент получает GET /manifest при запуске
  -> клиент сравнивает SHA-256
  -> клиент скачивает только изменённые blobs
  -> перезапуск Minecraft активирует новые моды
```

## Модель хранения

Manifest содержит логические пути и SHA-256. Blob-файл называется по своему hash, поэтому его URL неизменяем и может безопасно кэшироваться. Удаление записи из manifest не требует немедленно удалять blob: это оставляет основу для будущей истории версий и отката.

`draft.json` сохраняется независимо от `manifest.json`; при обновлении старой установки создаётся копированием опубликованного manifest. Admin API показывает разницу двух наборов по пути, стороне и содержимому, игнорируя время повторной загрузки. На Java операции хранилища синхронизированы, Node-mock сериализует обращения, чтобы одновременные изменения не терялись.

Control 0.2.2 передаёт ревизию показанного черновика при публикации. Агент сравнивает её с текущей под той же блокировкой, что защищает запись; несовпадение даёт HTTP 409 без публикации. Блокировки редактирования отдельного файла между панелями нет. Старые клиенты без ревизии работают по прежнему протоколу.

Публикация сохраняет временные копии на диске, проверяет все SHA-256 и при обрабатываемой ошибке восстанавливает затронутые файлы и manifest. Это защита от неудачной операции записи, а не журнал транзакций для аварийного выключения или история опубликованных релизов.

Панель использует fflate для ограниченного чтения метаданных архивов. Она не выполняет код загружаемых JAR. На Windows `dragDropEnabled: false` оставляет обработку перетаскивания HTML5-интерфейсу WebView2.

## Граница доверия

Public API не требует авторизации, потому что клиенты должны скачивать сборку. Admin API проверяет индивидуальные ключи устройств с ролями владельца и администратора. Главный ключ проекта позволяет восстановить владельца. Одноразовые приглашения создают только ожидающие заявки, подтверждение выполняет владелец. Реестр и последние 250 событий находятся в `udmc-sync/admin-access.json`; в нём нет исходных ключей. Встроенный сервер ограничивает заявки и неудачные попытки авторизации по IP, но не реализует TLS или общую защиту от DoS. Reverse proxy или VPN остаётся частью безопасной production-схемы. [Модель доступа](administrators.md).

RCON является отдельным TCP-протоколом Minecraft. Он не проходит через HTTP API и подключается непосредственно из нативной части UDMC Control. Перезапуск выполняется совместно: агент корректно завершает Minecraft, а wrapper или внешний supervisor запускает процесс снова.

## Следующие этапы

- handshake при подключении к Minecraft-серверу;
- история manifest и откат;
- постоянные резервные копии и восстановление после аварийного выключения;
- NeoForge для 26.x и Forge для 1.20.1;
- кодовая подпись Windows-инсталлятора.

## Генерация и доверие

Каталог `minecraft/agent-catalog.json` содержит реально собираемые варианты Fabric и NeoForge. Общие API, подписи, хранилище, синхронизация и клиентский экран находятся в `minecraft/udmc-sync-common`. Проекты загрузчиков предоставляют точки входа, игровые адаптеры и чтение метаданных: Fabric JSON/предикаты Fabric и NeoForge TOML/Maven ranges/Jar-in-Jar. NeoForge FML проверяется отдельно от версии NeoForge. Rust включает шаблоны мода в бинарник Control и отдаёт их без единого изменения: файл, который выдаёт панель, — тот, с которым она собрана. Ключи PKCS#8/X.509 создаёт сам сервер при первом запуске; клиент получает только публичный ключ и только от сервера, к которому подключается. Сменившийся адрес применяется молча, сменившийся ключ — никогда.

Подпись передаётся заголовком `x-udmc-signature` над точными UTF-8 байтами JSON. `releaseSequence` возрастает при публикации. Клиент проверяет подпись до разбора manifest, затем project ID, версию Minecraft и тип загрузчика, безопасные пути, размеры и hashes. Личные файлы с несовпадающим содержимым не перезаписываются. При ошибке применения выполняется попытка восстановления; crash-consistent журнал транзакций пока отсутствует.

Официальные технические источники: [Fabric Loom](https://docs.fabricmc.net/develop/loom/), [метаданные NeoForge 1.21.1](https://docs.neoforged.net/docs/1.21.1/gettingstarted/modfiles/), [проверка зависимостей FML](https://github.com/neoforged/FancyModLoader/blob/1.21.1/loader/src/main/java/net/neoforged/fml/loading/ModSorter.java), [Ed25519 Dalek](https://docs.rs/ed25519-dalek/2.2.0/ed25519_dalek/), [Windows keyring backend](https://docs.rs/keyring/3.6.3/keyring/), [Tauri dialogs](https://v2.tauri.app/plugin/dialog/).
