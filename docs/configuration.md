# Конфигурация

UDMC Agent читает JSON-файл:

```text
<gameDir>/config/udmc-sync.json
```

Если файла нет, агент создаёт его при первом запуске. В готовых JAR из Control настройки берутся из встроенного `udmc-bootstrap.json`. Таблица ниже также описывает универсальный шаблон для разработчиков, который сам по себе не содержит ключей.

## Поля

| Поле | По умолчанию | Назначение |
| --- | --- | --- |
| `serverUrl` | `http://127.0.0.1:3077` | URL manifest и файлов для клиента |
| `apiHost` | `0.0.0.0` | адрес прослушивания API на сервере |
| `apiPort` | `3077` | порт API на сервере |
| `adminToken` | `change-me` | секрет для `/admin/*` |
| `clientSyncOnStart` | `true` | запуск синхронизации при старте клиента |
| `packId` | `udmc-main` | стабильный идентификатор сборки |
| `packName` | `UDMC Main Modpack` | отображаемое название |
| `packVersion` | `0.1.0` | версия новой сборки до первого manifest |
| `minecraftVersion` | определяется автоматически | фактическая версия Minecraft |
| `loaderType` | из шаблона | `fabric` или `neoforge`, определяется установленным агентом |
| `loaderVersion` | определяется автоматически | фактическая версия Fabric Loader или NeoForge |
| `languageLoaderVersion` | определяется автоматически | внутренняя версия FML для NeoForge; это не номер NeoForge, вручную не менять |
| `allowRemotePowerActions` | `false` | разрешение остановки и перезапуска через Admin API |
| `role` | `universal` в шаблоне | `server` или `client` в готовом JAR |
| `bootstrapId` | пусто | fingerprint конфигурации JAR, позволяет применить новый bootstrap |
| `manifestPublicKey` | пусто в шаблоне | Base64 X.509 SubjectPublicKeyInfo Ed25519, закреплённый ключ проекта |
| `manifestPrivateKey` | только сервер | Base64 PKCS#8 Ed25519; секрет, клиенту не выдаётся |
| `requireSignedManifest` | `true` в готовых JAR | отклонять неподписанные manifest |
| `allowInsecureHttp` | `false` | явное разрешение HTTP на клиенте для доверенной сети |

## Сервер

На сервере критичны `apiHost`, `apiPort` и `adminToken`. Значение `adminToken` должно быть длинным случайным секретом и не должно храниться в публичном репозитории.

Пример генерации токена в PowerShell:

```powershell
[Convert]::ToHexString([Security.Cryptography.RandomNumberGenerator]::GetBytes(32)).ToLower()
```

Название сборки и разрешение удалённого управления можно менять через UDMC Control. Версии Minecraft и загрузчика агент получает из запущенного сервера и обновляет в manifest автоматически.

## RCON

RCON настраивается штатно в `server.properties`, а не в `udmc-sync.json`:

```properties
enable-rcon=true
rcon.port=25575
rcon.password=replace-with-another-long-secret
broadcast-rcon-to-ops=false
```

`25575` — стандартный порт, но в UDMC Control можно указать любой настроенный порт. В поле хоста разрешены IP и домены без `http://`. RCON работает по обычному TCP без шифрования, поэтому не публикуйте его напрямую в интернет.

## Клиент

У готового клиентского JAR конфиг формируется автоматически, игрок ничего не вводит. В нём нет административного токена и закрытого ключа. При обновлении bootstrap с прежними ключами меняются параметры подключения, но не версия опубликованной сборки. Отличающийся ключ/проект/роль не подменяются молча. Переключайте проект через отдельный профиль Minecraft.

## Хранилище

На сервере агент создаёт:

```text
<gameDir>/udmc-sync/manifest.json
<gameDir>/udmc-sync/draft.json
<gameDir>/udmc-sync/blobs/<sha256>.<ext>
```

`manifest.json` - опубликованная сборка для клиентов. `draft.json` - подготовленные администратором изменения. При отсутствии черновика агент копирует опубликованную сборку. Не редактируйте эти файлы вручную при работающем API.

`udmc-sync/admin-access.json` - серверный реестр устройств, хешей ключей, приглашений и журнала. Сохраняется при перезапусках и обновлениях JAR с прежними ключами. Не редактируйте его при работающем сервере и не публикуйте в GitHub. Главный `adminToken` остаётся средством восстановления владельца, другие панели используют персональные ключи. [Доступ и восстановление](administrators.md).

Во время публикации изменяемые серверные файлы временно копируются в `udmc-sync/publish-backup-*`. При обрабатываемой ошибке записи агент пытается восстановить файлы и оба manifest. После успешной операции временные копии удаляются; если восстановление тоже завершилось ошибкой, копии остаются для ручного восстановления. Аварийное выключение процесса или машины требует проверки администратором.

Служебный `config/udmc-sync.json` запрещено включать в сборку, чтобы случайно не раздать токен администратора. Управляемые пути не могут проходить через символические ссылки.

На клиенте состояние синхронизации хранится в:

```text
<gameDir>/udmc-sync/client-state.json
```

Этот файл позволяет удалять только те файлы, которые ранее установил UDMC.

В `client-state.json` также хранится последний принятый `releaseSequence`. Возврат к меньшему номеру блокируется. Удаление состояния убирает эту защиту и учёт старых файлов; не используйте это как обычный способ отката. Для возврата файлов публикуйте новую версию с прежним содержимым.
