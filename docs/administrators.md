# Несколько администраторов

Нужны UDMC Control и серверный агент версии 0.2.2 или новее. Все панели работают с одной сборкой и одним черновиком на сервере, не с отдельными копиями. Перед публикацией проверяйте весь черновик: там могут быть изменения другого администратора. Если черновик изменился после показанного вам состава, публикация из Control 0.2.2 отклоняется, список обновляется и требует новой проверки. Совместного редактирования с блокировкой отдельных файлов пока нет; старые API-клиенты без номера ревизии этой защитой не пользуются.

## Владелец

Ключ доступа к проекту создаёт сам сервер и отдаёт его той панели, которая назвала код привязки. Эта панель регистрирует отдельный ключ своего компьютера с ролью владельца. Главный ключ остаётся средством восстановления, а не приглашением для друзей.

1. Откройте **Устройства → Пригласить**.
2. Скопируйте приглашение и передайте другу приватным сообщением. Оно действует 15 минут и используется один раз. Содержит адрес сервера и временный секрет, но не главный ключ.
3. Дождитесь заявки: рядом с **Устройствами** появится счётчик.
4. Сверьте короткий код заявки с кодом на экране друга, например по голосовой связи. Имя компьютера само по себе не является доказательством личности.
5. Нажмите кнопку разрешения, подтвердите сверку кода. Заявку можно отклонить; без решения она истекает через 30 минут.

Приглашение с `127.0.0.1` или `localhost` не подходит другу на другом ПК. Сначала подключите вашу панель по общему HTTPS-адресу, LAN/VPN-адресу, доступному обоим. Для обычного HTTP требуется явное разрешение доверенной сети на каждой панели.

## Другой администратор

1. Установите UDMC Control на своём Windows-компьютере.
2. Откройте **Настройка сервера → Подключение → «У меня приглашение»**, вставьте приглашение и укажите понятное имя компьютера.
3. Отправьте заявку. Адрес подставится из приглашения; вводить серверный ключ не нужно.
4. Сообщите владельцу код из окна ожидания. После подтверждения панель подключится автоматически. Ожидающая заявка сохраняется при закрытии приложения.

Новый администратор может менять и публиковать сборку, выполнять команды и останавливать или перезапускать сервер: отдельного разрешения на это в конфиге больше нет — тот, кто дозвонился до API, и так может напечатать `stop` в консоли. Только владелец управляет приглашениями и доступом других устройств и только владелец может сохранить резервную копию проекта. Пароль прямого RCON не передаётся приглашением; для консоли через агент он не нужен.

## Устройства и отзыв

Владелец видит имя, роль, состояние, последний адрес, время активности, ожидающие заявки и журнал доступа. «Активен» означает запрос с этим ключом за последние 90 секунд, а не постоянное соединение. Страница обновляется примерно раз в 5 секунд, пока панель открыта. Хранятся последние 250 событий, включая решения по доступу и результат изменяющих API-запросов, без их тел и секретов.

Кнопка отзыва блокирует **следующие** запросы соответствующего ключа. Уже выполняющийся запрос может завершиться. Вернуть доступ можно новым приглашением. Самого себя панель отозвать не позволяет, чтобы не потерять доступ случайно. Неиспользованное приглашение можно отменить.

Это список ключей устройств, не аппаратная аттестация и не антивирус. При краже ключа злоумышленник может представиться тем же компьютером. За прокси или VPN виден адрес непосредственного соединения с агентом; заголовок `X-Forwarded-For` не считается доверенным. Нет геолокации, фоновых уведомлений при закрытой панели и гарантированного обнаружения взлома.

## Восстановление и секреты

- Резервную копию проекта владелец сохраняет в **Настройка сервера → Подключение → «Резервная копия»**. Там же лежит ключ подключения: его вводят вручную, когда панель ставят на новый компьютер и пригласить некому — тогда из этой копии берут ключ восстановления.
- Файл мода передавать можно кому угодно: секретов в нём нет. А вот `config/udmc-sync.json`, резервную копию проекта и главный ключ — нельзя: их обладатель может выдать себя за проект и восстановить владельца без приглашения.
- При переносе владельца на новый ПК привяжитесь заново: сбросьте привязку на сервере (`resetPairing` в конфиге, перезапуск), возьмите новый код и введите его в новой панели. Прежние панели при этом теряют доступ, что обычно и требуется.
- На сервере `udmc-sync/admin-access.json` содержит только SHA-256 случайных ключей/приглашений и журнал. Ключи имеют 256 бит энтропии, не являются пользовательскими паролями. Реестр сохраняется атомарно и переживает перезапуск.
- Сохраняйте резервную копию реестра вместе с сервером. Его удаление сбрасывает все разрешения устройств, но не главный ключ. Восстановление старой копии может вернуть отозванные разрешения; после восстановления пересмотрите список.
- При смене главного ключа, ID проекта или ключа подписи старый реестр не принимается. Два штатных случая сервер разбирает сам: сброс привязки (`resetPairing`) убирает реестр в сторону как `admin-access.<время>.bak.json`, и прежние панели теряют доступ; восстановление резервной копии проекта при привязке переподписывает реестр, и устройства остаются. Если же конфиг изменили вручную, на **остановленном** сервере сохраните приватную копию `admin-access.json` и уберите исходный файл из служебной папки. После запуска заново подключите владельца и выдайте приглашения. Обычное обновление мода этого не требует.
- Если украдены конфиг сервера или резервная копия проекта, отзыва одного устройства недостаточно: у вора есть ключ подписи. Нужна смена секретов проекта, а игрокам придётся заново принять новый ключ. Автоматической ротации пока нет.

Администратор сборки имеет широкие права: может раздать клиентам код мода и загрузить серверный мод. Роли API не изолируют вредоносный код на машине сервера. Давайте доступ только доверенным людям, используйте HTTPS и резервные копии. Отзыв UDMC-ключа не отзывает отдельный пароль RCON или доступ к хостингу.
