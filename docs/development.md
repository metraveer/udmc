# Разработка

## Требования

- Node.js `20+` и npm;
- Java Development Kit `25` для Gradle и профилей 26.x, а также JDK `21` для профилей 1.21.1;
- Rust stable;
- Windows 10/11, WebView2 и Microsoft C++ Build Tools для сборки Tauri.

Gradle устанавливать отдельно не нужно: проект содержит Wrapper.

## Установка зависимостей

```powershell
npm ci
```

## Node API-mock

Mock повторяет API серверного агента и нужен только для разработки UDMC Control.

```powershell
$env:UDMC_ADMIN_TOKEN = "dev-token"
npm run server
```

API будет доступен по адресу `http://127.0.0.1:3077`.

## Предпросмотр интерфейса

```powershell
npm run admin:preview
```

Предпросмотр открывается на `http://127.0.0.1:4173`. Это тестовый HTTP-стенд статического интерфейса, а не отдельная браузерная версия продукта.

Команды `admin:preview`, `admin:dev` и `admin:build` автоматически копируют fflate, smol-toml, Lucide, marked, DOMPurify, i18next и их лицензии из `node_modules` в `ui/vendor`. Код интерфейса не зависит от CDN. Каталог требует интернет для API, значков и JAR. При запуске Tauri напрямую сначала выполните `npm run admin:prepare`.

## Переводы интерфейса (следующий выпуск)

Используется **i18next 26.4.0**, а не замена текста через MutationObserver. Исходные словари: `apps/admin-desktop/ui/locales/ru.json` и `en.json`. `admin:prepare` собирает из них локальный ESM-ресурс; сеть для локализации не нужна. Добавляйте ключ в оба словаря и используйте `t("Ключ сообщения", parameter)` в JS или `data-i18n` / `data-i18n-title` / `data-i18n-aria-label` / `data-i18n-placeholder` для статического HTML. Текущие ключи соответствуют исходному русскому тексту; переменные обозначены `{0}`, `{1}`. Не переводите имена, команды, пути, адреса и описания авторов модов.

Для чисел с существительными используйте `countText` и стандартные i18next-формы `_one`, `_few`, `_many`, `_other`, не собственные вычисления `% 10`. Строки с параметрами вставляются через `textContent` и атрибуты, не `innerHTML`. Тест проверяет полноту словарей, параметры, отсутствие неотмеченного русского текста в JS/HTML, английский запуск, склонения и сохранение выбора языка.

При первом запуске русский выбирается для системного `ru`, иначе английский. Ручной выбор хранится глобально в `udmc-language`, отдельно от серверных профилей. Смена языка перезагружает документ WebView, не процесс приложения; незагруженные локальные файлы требуют подтверждения. Во время защищённого редактирования или серверной команды смена заблокирована. Вкладка, источник каталога, фильтры, несохранённое имя сборки и история восстанавливаются из отдельного `sessionStorage` каждого профиля, в пределах текущего сеанса приложения. Известные панели ключи/пароли маскируются перед сохранением истории; произвольные серверные ответы могут содержать другие чувствительные сведения, поэтому не экспортируйте историю без проверки.

Игровые экраны используют штатную локализацию Minecraft: `Component.translatableWithFallback` и `minecraft/udmc-sync-common/src/main/resources/assets/udmc_sync/lang/{en_us,ru_ru}.json`. Язык игры независим от языка Control. `Messages` передаёт ключ и параметры, а для журналов и неизвестного языка даёт английский fallback; отдельного самописного движка выбора языка нет. Основные ошибки синхронизации и обновления имеют переводимые коды; неизвестная техническая ошибка отсылает к `logs/latest.log`, а не выдаётся за успех. Причины входа `missing`, `incompatible` и `outdated` тоже являются переводимыми компонентами. У чистого клиента ещё нет ресурсов UDMC, поэтому его disconnect/чат использует общий двуязычный EN/RU fallback с кликабельной ссылкой; установленный агент показывает язык Minecraft.

Диагностика модов в API содержит `code`, `args` и совместимое поле `message`. `admin:prepare` добавляет ключи `udmc_sync.diagnostic.*` из игровых словарей в ресурсы i18next, преобразуя индексированные параметры `%1$s` в `{0}`. Переводы не дублируются вручную. Control переводит только известные коды с проверенными параметрами; неизвестные ответы старого/будущего агента показывает как текст. При изменении ревизии состава результат проверки помечается устаревшим. Изменения файлов вне UDMC требуют повторного сканирования, они не определяются по ревизии панели.

Все ожидаемые ошибки HTTP API используют совместимый JSON-конверт `{ "error": "English fallback", "code": "STABLE_CODE", "args": [] }`; workspace-конфликты дополнительно возвращают `workspace`. Статус HTTP не заменяется кодом. `args` предназначен для буквальных имён устройств, путей и других параметров, которые переводить нельзя. `agentJson` сохраняет `status`, `code`, `args` и `workspace`, а `formatAgentError` выбирает только известный шаблон i18next с защитой от произвольных ключей. Не добавляйте новый `text.includes` для нового агента: выдайте стабильный код на Java-стороне и добавьте оба перевода. Текстовый разбор в `http.js` существует только для совместимости с ранее выпущенными агентами; неизвестный будущий код должен показать `error`, а не маскироваться общей успешной формулировкой.

Ошибки Tauri-команд используют типизированный контракт `native_error.rs`: `{ code, args, fallback, outcomeUnknown }`. Все команды, которые могут завершиться ошибкой, возвращают `NativeResult`; `formatAppError` в `http.js` переводит известный код через i18next, для `outcomeUnknown` добавляет предупреждение о возможно выполненной команде, а для неизвестного кода показывает английский `fallback`. Технические подробности ограничиваются 1024 символами и очищаются от управляющих символов ещё на Rust-стороне. Неошибочные служебные статусы обновления агентов (`updateReason`, состояния операции) передаются кодами `AGENT_UPDATE_*` из `AgentDistribution`/`AgentUpdater` и переводятся `agentStatusMessage`; старые агенты сохраняют исходный текст. Не добавляйте новые строковые сравнения ошибок ни в Rust, ни в JS. Длинные тексты, эмулированный масштаб и минимальный размер окна проверены нативно 29.08.2026 (`.qa/native-ui-0829/`); реальная смена Windows-масштаба дисплея не выполнялась. Полную локализацию продукта не считать проверенной только по тестам WebView.

### Источники каталога

Три источника: Modrinth (без ключа), GitHub Releases (без ключа) и CurseForge. CurseForge работает только с персональным ключом Core API из [console.curseforge.com](https://console.curseforge.com/): пользователь сохраняет его на вкладке каталога, ключ хранится в защищённом хранилище Windows профиля (`curseforge-api-key`) и передаётся только на `api.curseforge.com`. Показываются лишь моды, авторы которых разрешили раздачу через API (`allowModDistribution` не `false`); файлы без `downloadUrl` отклоняются кодом `CURSEFORGE_DISTRIBUTION_BLOCKED`. Загрузки идут только с `edge.forgecdn.net`/`mediafilez.forgecdn.net`, проверяются размером и SHA-1, миниатюры — только с `media.forgecdn.net` (разрешён в CSP). Обязательные зависимости CurseForge не устанавливаются автоматически — их называет проверка состава. Важно про виды ключей: подходит только **организационный ключ Core API** со страницы «API keys» консоли console.curseforge.com (вид `$2a$10$...`); свежесозданный ключ первые ~десятки минут может отдавать 403 на части эндпоинтов (в т.ч. поиск) и затем открывается сам. Не подходят: UUID-токены «My API Tokens» со старого сайта авторов legacy.curseforge.com (это загрузка своих модов) и «Profile API key» (`cfc_pat_...`) из раздела Profile консоли. Серверная `validSource` принимает провайдеры `modrinth`, `github`, `curseforge` (числовые id); обработчик загрузки дочитывает тело до 64 МиБ перед ранним отказом, чтобы панель получала типизированный 400, а не разрыв соединения. Живой smoke-тест: `UDMC_CURSEFORGE_KEY=<ключ> cargo test --manifest-path apps/admin-desktop/src-tauri/Cargo.toml live_catalog_search -- --ignored --nocapture`.

### Страница настроек и переводчик описаний

Язык и переводчик живут на странице «Настройки» (вид `settings`); селектора языка в шапке больше нет, но элемент `languageSelect` и вся механика смены языка (подтверждение потери локальных файлов, busy-гейтинг, перезагрузка документа) не изменились. Перевод описаний каталога — только по кнопке «Перевести» (видна при русском языке интерфейса) через официальный **Yandex Translate API v2**: пользователь создаёт в Yandex Cloud сервисный аккаунт с ролью `ai.translate.user`, выпускает API-ключ и копирует folder id; пара хранится в защищённом хранилище Windows под именем `translator-key` (JSON `{provider,key,folder}`, глобально для приложения, не по профилям серверов). Rust-команда `translate_texts` (`translator.rs`) шлёт запросы только на `translate.api.cloud.yandex.net` по HTTPS без редиректов, ограничивает пакет 32 текстами, 4000 символами на текст и 9000 суммарно, и возвращает коды `TRANSLATOR_*` (переводятся в `http.js`). `ui/assets/translate.js` собирает текстовые узлы описаний (TreeWalker, `code`/`pre` пропускаются), режет на пакеты по лимитам, кэширует оригиналы для «Оригинала» и сбрасывает состояние при смене выбранного мода; хранилище читается лениво — только при открытии настроек или клике перевода. Встроенный Chromium Translator API в WebView2 существует, но модели не доставляются (нет компонентной инфраструктуры Chrome) — используется автоматически лишь если `availability()` вернёт `available`. Названия модов не переводятся. Живой smoke-тест: `UDMC_TRANSLATOR_KEY=<ключ> UDMC_TRANSLATOR_FOLDER=<folder> cargo test --manifest-path apps/admin-desktop/src-tauri/Cargo.toml live_translation -- --ignored --nocapture`.

### Тёмная тема и «слотовая» фаска

Приложение использует единственную тёмную тему (`color-scheme: dark`, тёмный заголовок окна через `theme: Dark` в tauri.conf.json). Токены в `:root` styles.css: полотно `--canvas #131418`, поверхности `--surface #1b1d23`, колодцы `--well`, лавовый акцент `--accent #ff6a45`. Фирменный элемент — фаска в духе слота инвентаря Minecraft: приподнятые элементы (кнопки, чипы) используют `--bevel-raised`, утопленные (поля ввода, консоль, миниатюры) — `--bevel-sunken`; нажатие кнопки смещает её на 1px. Новые элементы должны использовать токены и один из двух беvelей, а не собственные цвета; текстовые метки-«кикеры» — caps + letter-spacing. Плотность намеренно высокая (кнопки 34px, ячейки таблиц 8px) — не возвращайте крупные отступы. Строки `.workspace:has(dialog[open]) { overflow-y: hidden; }` и `dialog { overscroll-behavior: contain; }` защищены тестом дословно.

### Игровой адрес и подключение из игры

Администратор задаёт публичный игровой адрес (host или host:port) в разделе агентов; он хранится в `udmc-sync.json` (`gameAddress`), валидируется `UdmcConfig.normalizeGameAddress` (код ошибки `GAME_ADDRESS_INVALID`) и отдаётся публичным `GET /agents/info`. После успешной проверки сборки клиент запрашивает адрес best-effort и показывает кнопку «Подключиться к серверу»: она уважает `allowsMultiplayer()` (родительский контроль оставляет её выключенной с ванильной подсказкой), добавляет сервер в штатный список серверов игрока (без дубликатов) и при включённом предупреждении о сторонней игре открывает штатный `SafetyScreen`, чей поток ведёт в список с готовой записью; прямой `ConnectScreen` используется только когда предупреждение уже отключено самим игроком. Пустой адрес полностью скрывает кнопку. Ошибка публикации при непройденной проверке состава возвращает `409 PUBLISH_BLOCKED_BY_VALIDATION` с количеством проблем, а не 500.

## Агенты Fabric и NeoForge

```powershell
npm run minecraft:build
```

Можно также выполнить Wrapper напрямую:

```powershell
cd minecraft/udmc-sync-fabric
./gradlew.bat build
```

Для NeoForge 1.21.1 используется тот же Wrapper с другой рабочей папкой:

```powershell
cd minecraft/udmc-sync-neoforge
../udmc-sync-fabric/gradlew.bat build
```

Общий код находится в `minecraft/udmc-sync-common`; проекты загрузчиков подключают его как source set. NeoForge использует ModDevGradle 2.0.144, NeoForge 21.1.248 и Java 21. Его `loaderVersion` в TOML описывает FML, а не NeoForge. Версия FML определяется во время работы, базовое значение шаблона соответствует зависимости 4.0.43.

Одного Fabric Loader недостаточно для загрузки языковых ресурсов мода. Поэтому Fabric-агенты включают два небольших официальных модуля: `fabric-api-base` и `fabric-resource-loader-v1` (26.x) либо `fabric-resource-loader-v0` (1.21.1). Версии закреплены отдельно для каждой игры в `build.gradle`. Модули и их Apache-2.0 LICENSE остаются вложенными JAR; полный Fabric API и дополнительная ручная установка не требуются. Встроенные версии учитываются диагностикой зависимостей, но не скрывают явно добавленный несовместимый мод. NeoForge использует собственную загрузку ресурсов и не включает Fabric-модули. Источники: [Fabric: переводы](https://docs.fabricmc.net/develop/text-and-translations), [Fabric Resource Loader](https://github.com/FabricMC/fabric-api/blob/26.2/fabric-resource-loader-v1/README.md), [NeoForge: локализация](https://docs.neoforged.net/docs/resources/client/i18n/).

## Проверки

```powershell
npm test
npm run smoke
node --check apps/admin-desktop/ui/assets/admin.js
cargo test --manifest-path apps/admin-desktop/src-tauri/Cargo.toml
cargo fmt --manifest-path apps/admin-desktop/src-tauri/Cargo.toml --check
cargo clippy --manifest-path apps/admin-desktop/src-tauri/Cargo.toml --all-targets -- -D warnings
```

Runtime-проверка агента требует отдельного тестового Minecraft-сервера и клиента; обычная Gradle-сборка не запускает игру.

`npm test` также запускает настоящие ES-модули панели в изолированном jsdom: защищённые настройки, отказ хранилища ключей, отмена, запоздавшие ответы, потеря соединения, статусы RCON и открытие каталога. Windows bridge и HTTP здесь подменены; это проверка поведения DOM, не WebView-разметки. jsdom нужен только разработчикам и не входит в установщик. Для ESM используется `--experimental-vm-modules`.

Rust проверяет RCON через локальный TCP-сервер: точный пароль, отказ авторизации, пустые и задержанные составные ответы, обрыв, тайм-аут, повреждённые пакеты и лимиты. Пакеты ограничены 64 КиБ, весь входящий обмен 4 МиБ. Для проверки Windows-процессов:

```powershell
npm run admin:prepare
cargo build --manifest-path apps/admin-desktop/src-tauri/Cargo.toml
npm run admin:test:instance
```

Последняя команда запускает только debug-бинарник с уникальным тестовым профилем, проверяет второй запуск и три серии по восемь запусков, затем завершает только свои процессы. Нужен Windows-сеанс с WebView2. Вручную дополнительно проверьте восстановление свёрнутого окна. В `startup.rs` системная файловая блокировка сериализует создание обработчика single-instance; оставшийся пустой lock-файл не означает работающий процесс и не требует удаления.

`httpTest` входит в Gradle `check` каждого профиля: настоящее API, подписанная публикация, клиентская синхронизация и удаление, стороны файлов, сохранность личных изменений, конфликты ревизий, медленная загрузка, очистка после ошибки и ограничения размеров. Передача 96 МиБ выполняется с `-Xmx64m`, чтобы обнаруживать возврат к буферизации целого файла. Minecraft при этом не запускается. [Отчёт 0.2.4](testing-0.2.4.md).

`accessTest` входит в Gradle `check` для каждого профиля: приглашения, подтверждение владельцем, запрет повышения роли, отзыв после перезапуска, срок действия, ограничение попыток, привязка реестра к ключам проекта и реальные HTTP-запросы к изолированному API. `npm test` проверяет формат приглашений, транспорт ключей без redirects, отсутствие дублирующих полей и условия обновления NSIS.

Для read-only проверки настоящего Windows-окна можно запустить Gradle-задачу `accessUiFixture`. Она создаёт временный агент на loopback, печатает адрес и отдельный URL остановки, использует только тестовый ключ `udmc-ui-fixture-only`. В debug-сборке переменная `UDMC_TEST_PROFILE` (1-24 символа `a-z0-9-`) включает отдельные WebView-папку, заголовок окна и пространство Credential Manager. Необязательная `UDMC_TEST_CONNECTION` содержит JSON `{ "url": "http://127.0.0.1:PORT/", "token": "udmc-ui-fixture-only" }`. Другие хосты запрещены. В release этот код не компилируется. При обычном завершении тестовое хранилище соединения очищается; после проверки остановите fixture через напечатанный POST URL. Рабочую установленную программу для тестов не используйте.

`modCheckTest` проверяет переиспользование личных модов, конфликт ID, подтверждение для конкретного хеша, резервную копию и запрет публикации без обязательной зависимости. `npm test` также проверяет подбор зависимостей Modrinth и нормализацию адресов. Публичный сетевой smoke-тест запускается отдельно: `cargo test --manifest-path apps/admin-desktop/src-tauri/Cargo.toml live_catalog_download -- --ignored --nocapture`. Он скачивает и проверяет Fabric API без выполнения кода мода.

`localizationTest` входит в Gradle `check` каждой платформы: полнота RU/EN, параметры, настоящие Minecraft-компоненты, HTTP-диагностики и зависимые от встроенных модулей проверки. Тест открывает готовый JAR, сверяет языковые файлы, регистрацию/версии вложенных Fabric-модулей и наличие их LICENSE. `modCheckTest` дополнительно проверяет точное сопоставление путей: конфликт `library.jar-extra.jar` не разрешает удаление постороннего `library.jar`.

Fabric дополнительно запускает `agentPackageTest` на настоящем собранном JAR и его клиентском варианте. Он проверяет согласованность `bundledMods`, регистрацию вложенных модулей, их ID/версии и зависимости; неизвестные, повторные, пропавшие модули и небезопасные пути отклоняются. `serverLifecycleTest` проверяет, что подготовка конфигурации не открывает HTTP-порт, ошибка привязки API прерывает запуск и остановка освобождает порт. Сам API теперь запускается после успешного `DedicatedServer.initServer`, а не на стадии Fabric Loader, поэтому отказ Minecraft запускаться из-за EULA не оставляет фоновый API-процесс.

Для доступа к экрану Minecraft используется небольшой адаптер `src/platform/classic` (1.21.1, 26.1.2) или `src/platform/modern` (26.2). Клиентские и серверные mixin-конфигурации разделены; генератор включает только соответствующую роли.

`securityTest` проверяет подписи, отказ от HTTP без разрешения, защиту от отката, несовпадение Minecraft и загрузчика, атомарность загрузок до применения, личные файлы, импорт серверных файлов и запрет публикации секретного JAR. Rust-тесты проверяют изоляцию секретов в клиентских JAR и формат ключей.

NeoForge дополнительно запускает `metadataTest`: TOML, Maven-диапазоны, FML, стороны и типы зависимостей, циклы порядка загрузки, несколько корневых модов, встроенные библиотеки и неоднозначные вложенные версии. `npm test` проверяет NeoForge в генераторе и Modrinth, старые Fabric-настройки и выбор стороны ручной загрузки.

Для испытания именно сгенерированных JAR выполните `cargo test --manifest-path apps/admin-desktop/src-tauri/Cargo.toml export_neoforge_runtime_fixture -- --ignored --nocapture`. По умолчанию команда создаёт отдельную папку `.qa/neoforge-1.21.1-runtime-*`, пару JAR и приватный `fixture.json`, не обращаясь к Windows Credential Manager. Затем из NeoForge-проекта запустите `../udmc-sync-fabric/gradlew.bat runClient -Pudmc_packaged_test -Pudmc_run_dir=ABSOLUTE_CLIENT_PATH` или `runServer` с серверной подпапкой. Флаг отключает подключение development source set мода, чтобы загружался JAR из `mods`. Это всё ещё среда ModDevGradle, не проверка обычного установщика NeoForge. Сервер слушает только loopback; Minecraft EULA в fixture не принимается. Не используйте рабочий профиль, мир или ключи. После испытания закройте клиент и остановите сервер.

### Самообновление готового клиента

Opt-in экспорт поддерживает `UDMC_RUNTIME_TEMPLATE` из каталога, например `fabric-26.2` или `neoforge-1.21.1`. Реальное имя новой папки имеет вид `.qa/<template>-runtime-*`; всегда используйте напечатанный путь. Встроенные шаблоны Control сначала собираются обычным `npm run minecraft:build`. Для тестового обновления соберите отдельный агент той же платформы с более высокой версией, например `build -Pmod_version=0.3.1` при базовой 0.3.0, и передайте абсолютный путь к нему через `UDMC_RUNTIME_UPDATE_JAR` перед Rust-экспортом. Экспорт создаст `client-next.jar` с теми же публичными настройками и заново сформирует `update.zip` из следующего клиентского и серверного JAR. Так проверяется настоящий переход версии обеих ролей, а не только повторная упаковка текущего шаблона. Это не выпуск: `package.json`, каталог и установщик не повышаются, тестовый JAR в приложение не копируется.

Из проекта нужного загрузчика доступны действия `agentRuntimeFixture -Pudmc_fixture=ABSOLUTE_FIXTURE_ROOT -Pudmc_action=ACTION` (тот же Gradle Wrapper). Для Fabric укажите также `-Pminecraft_version=VERSION` во всех командах. Порядок:

1. `serve`: настоящий `UdmcHttpApi` и подпись на loopback, без Minecraft-сервера/мира. Дождитесь сообщения готовности; команда остаётся работать.
2. В другом терминале `publish`: передача `client-next.jar` через защищённый HTTP endpoint с ревизией и сессией.
3. `runClient -Pudmc_packaged_test -Pudmc_run_dir=ABSOLUTE_FIXTURE_ROOT/client`: запускается установленный JAR из `mods`. Нужен штатный экран готового обновления.
4. `waiting`: проверка живой исходной JVM, неизменного установленного JAR и точных подготовленных байтов. Сохраняет контрольный хеш конфигурации.
5. Закройте игру её кнопкой, дождитесь завершения процесса; `applied` сверит новый JAR, точную `previous.jar` и неизменные настройки.
6. Повторите `runClient`, дождитесь успешной проверки; `restarted` дополнительно проверит журнал и отсутствие ошибки определения установленного агента. Затем штатно закройте игру и вызовите `stop` для API-стенда.

Fabric packaged-режим исключает из runtime classpath исходники UDMC и отдельные development-копии resource-loader модулей: они загружаются из готового JAR. Режим разрешён только в отмеченных `.qa` client/server-папках, проверяет платформу и использует Java 21 для 1.21.1, Java 25 для 26.x. Это Loom development-окружение с готовым модом, не испытание стороннего лаунчера. Настройка опирается на [публичный classpath API Loom](https://github.com/FabricMC/fabric-loom/blob/1.17/src/main/java/net/fabricmc/loom/task/AbstractRunTask.java).

Для проверки режима без UDMC на Fabric 26.2 существует отдельный `-Pudmc_test_without_agent`. Он разрешён только в отмеченном `.qa`-профиле с пустой папкой `mods`, исключает выход UDMC, но оставляет официальные resource-loader модули, которые Loom уже использовал при подготовке Minecraft-классов. Этот флаг нужен только тестам и не означает дополнительную зависимость игрока.

`scripts/runtime-agent-check.js` принимает только отмеченный runtime fixture внутри `.qa` и loopback. Действия `delivery`, `required`, `optional` и `restart-api` проверяют API без имитации игрового входа. `minecraft-protocol@1.66.2` не поддерживает Minecraft 26.x, поэтому login-действия для такой версии завершаются явным отказом; настоящий вход проверяется запущенным Minecraft-клиентом, а не подменяется успешным API-ответом. Действие `stop` включает power-actions только в этом fixture и вызывает `/admin/server/stop`, как Control; консольная команда `stop` здесь не используется, потому что она может закрыть API до отправки собственного HTTP-ответа.

Все fixture-файлы, включая ключи, остаются в игнорируемой `.qa`. Полный серверный вход в мир требует явного согласия пользователя с Minecraft EULA для каждого изолированного тестового сервера; `eula=true` нельзя переносить в другие fixture или рабочие серверы. Клиентское HTTP-испытание EULA не принимает и серверный мир не запускает.

## Выпуск и версия

`npm run minecraft:build` собирает каждый вариант из `minecraft/agent-catalog.json` и копирует JAR в `apps/admin-desktop/src-tauri/agent-templates/`. Rust включает их в бинарник. Релизная сборка Control отказывается собираться без шаблонов или при несовпадении их версии с приложением. Fabric 1.21.1 использует remap Loom и Java release 21; Fabric 26.x обычный Loom и release 25; NeoForge 1.21.1 ModDevGradle и release 21. Один JAR нельзя сделать совместимым с другой версией игры или загрузчиком заменой строки в метаданных.

```powershell
npm run release:build
npm run release:build -- minor
```

Первая команда повышает patch-версию, вторая minor. `package.json` является источником версии; npm hook синхронизирует Tauri, Cargo и Gradle. Затем проверяются Node-тесты и собираются все агенты и установщик. Если сборка прервалась, `npm run release:build -- --retry` повторит её без нового повышения. Низкоуровневый `npm run admin:build` не меняет версию, что нужно CI и повторяемым сборкам. `npm run version:check` проверяет согласованность метаданных. Установленное приложение само новые версии не скачивает.

Tauri CLI закреплён на 2.11.4 из-за собственного NSIS-шаблона. При смене CLI нужно сверить шаблон с upstream и повторить проверку обновления. Причина и лицензия: [windows/README.md](../apps/admin-desktop/src-tauri/windows/README.md).

`npm test` проверяет автоопределение архивов и безопасность путей. Smoke-тест проверяет отдельный draft/live workflow, удаление и отмену, редактирование, сброс и параллельную загрузку. Gradle-задача `storeTest` запускается из `check` и проверяет серверные файлы, миграцию, целостность blobs и откат при ошибках записи.

Для ручной проверки интерфейса можно выполнить `node scripts/create-ui-fixtures.js`. Файлы в `tmp/ui-fixtures/` содержат только тестовые метаданные, это не рабочие Minecraft-моды. Направляйте их только в отдельное хранилище mock-сервера через `UDMC_DATA_DIR`.

Для клиентских экранов запустите из корня:

```powershell
node scripts/client-ui-fixture.js --language ru_ru --scenario conflict --minecraft 26.2
```

Скрипт печатает новый уникальный абсолютный путь `.qa/client-ui-*` и loopback-порт. В другом терминале из `minecraft/udmc-sync-fabric` выполните `./gradlew.bat runClient '-Pminecraft_version=26.2' '-Pudmc_run_dir=ABSOLUTE_FIXTURE_PATH'`, подставив напечатанный путь. Поддерживаются языки `en_us`/`ru_ru`, сценарии `conflict` (личный мод другой версии), `verified` (состав уже совпадает), `updated` (нужно скачать мод и перезапустить игру) и Fabric-версии из каталога. Версия `runClient` должна совпадать с аргументом fixture. Это development classpath, не испытание установленного сгенерированного агента. Нет мира, настоящих ключей и подключения к рабочему серверу.

После проверки закройте игру. Для штатной остановки HTTP-стенда прочитайте `fixture.json` только из созданной тестовой папки, проверьте `kind` = `udmc-client-ui-test` и отправьте `POST http://127.0.0.1:PORT/__stop` с заголовком `Authorization: Bearer STOP_TOKEN` из этого файла. Не публикуйте `fixture.json` и не используйте рабочий профиль для этих тестов.
