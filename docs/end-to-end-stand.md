# Сквозная проверка: настоящий клиент против настоящего сервера

Все ошибки, из-за которых игроки не могли зайти на сервер, жили в одном месте — на пути
игрока: загрузка конфига, применение настроек из JAR, проверка при входе. Ни один
существующий тест этот путь не проходил целиком: Java-тесты работают с API без игры, а
`runtime-agent-check.js` подключается библиотекой, а не настоящим клиентским модом.

Стенд ниже поднимает **настоящий сервер Minecraft** с серверным агентом и **настоящий
клиент** с клиентским агентом, собранные ровно так, как их собирает Control.

## Как поднять

```bash
npm run minecraft:build
```

```bash
npm run e2e:stand -- 26.2
```

Создаётся `.qa/fabric-26.2-e2e/` с ключами проекта, серверным и клиентским JAR, миром и
`fixture.json`. Каталог одноразовый: повторный запуск стирает прежний.

Сервер (API на 43077, игра на 43565):

```bash
cd minecraft/udmc-sync-fabric && ./gradlew runServer -Pminecraft_version=26.2 -Pudmc_packaged_test -Pudmc_run_dir=<путь>/.qa/fabric-26.2-e2e/server
```

Опубликовать клиентский агент и включить правило входа:

```bash
npm run e2e:admin -- publish-client require-on
```

Клиент, который сам подключается к стенду:

```bash
cd minecraft/udmc-sync-fabric && ./gradlew runClient -Pminecraft_version=26.2 -Pudmc_packaged_test -Pudmc_run_dir=<путь>/.qa/fabric-26.2-e2e/client -Pudmc_quick_join=127.0.0.1:43565
```

## Что проходить

Каждый сценарий — это подмена содержимого `client/mods` и `client/config` между запусками.

| Сценарий | Что положить | Что должно быть на экране |
| --- | --- | --- |
| Обычный вход | клиентский JAR, конфига нет | игрок в мире |
| Конфиг от другого проекта | клиентский JAR + чужой `udmc-sync.json` | игрок в мире, прежний конфиг в `udmc-sync-previous.json` |
| Мода нет | пустой `mods`, флаг `-Pudmc_test_without_agent` | отказ с двуязычной инструкцией и версиями сервера |
| Файл не тот | опубликовать пересобранный JAR, у игрока прежний | «версия та же, но сборка другая» |
| JAR из исходников | `raw-agent.jar` из стенда | «файл не настроен ни на какой сервер» |

Скриншот обязателен: две ошибки этого набора — невидимая строка и кнопка не в том блоке —
программные проверки не видели вовсе.

## Почему не в CI

Прогон требует настоящих клиента и сервера Minecraft с окном и загрузкой ассетов: это
минуты и графическая среда. Проверка делается руками перед выпуском, который меняет агентов.
