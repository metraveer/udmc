# UDMC API

Локальный URL по умолчанию:

```text
http://127.0.0.1:3077
```

## Public API

### `GET /health`

Возвращает состояние сервиса. `accessControl: true` означает поддержку устройств и приглашений серверным агентом.

### `GET /pair`

Говорит, ждёт ли этот сервер привязки, и как он себя называет: `{ unpaired, packName,
minecraftVersion, loaderType, fingerprint }` — отпечаток ключа подписи тот же, что видит игрок
на экране согласия. Ключа не требует и ничего секретного не содержит — панель
спрашивает это до того, как у неё вообще есть доступ.

### `POST /pair`

Забирает проект по коду привязки. Тело: `{ code }`, или `{ code, project }`, где `project` —
сохранённая копия проекта, которую надо поставить на место той, что сервер завёл себе сам.

Ответ содержит ключ доступа, открытый ключ проекта, его отпечаток, версии и порт API.
Закрытого ключа подписи здесь нет: сервер подписывает сборку сам, и ключ, которым можно выдать
себя за проект, не обязан ходить по сети ради привязки.

Ключа не требует: код и есть доказательство. Отвечает только пока сервер никем не занят; после
привязки — 409 `PAIRING_ALREADY_DONE`. Неверный код — 403 `PAIRING_CODE_INVALID`, и попытки с одного адреса
ограничены: 10 за минуту, дальше 429 `PAIRING_RATE_LIMIT`.

Код сравнивается без учёта регистра и дефисов: переписанный из консоли, он остаётся тем же
кодом.

### `GET /manifest`

Возвращает опубликованный manifest сборки — только те файлы, которые нужны игроку (`side`
`client` и `both`). Файлы со стороной `server` в публичном manifest не перечисляются: игроку
незачем знать имена и хеши серверных конфигов. Полный опубликованный manifest панель получает
в `GET /admin/files` (поле `published`).

Сервер добавляет `x-udmc-signature`: Base64 Ed25519-подпись точных UTF-8 байтов тела. До JSON-разбора клиент проверяет её закреплённым X.509 публичным ключом. Прокси не должен преобразовывать тело или терять заголовок. Поле `releaseSequence` растёт при публикации; клиент не принимает меньшее значение, чем уже сохранённое. Отсутствие поля у старого manifest трактуется как 0.

### `GET /files/<sha256>.<ext>`

Возвращает blob. Клиент обязан проверить SHA-256 после скачивания.

Без ключа отдаются только blob-ы, перечисленные в публичном manifest. Серверный файл и файл,
который лежит только в черновике, по хешу не получить — даже зная его: ответ 404. Запрос с
действующим ключом устройства (`x-udmc-token`) получает любой blob хранилища.

Агент отдаёт файлы потоком и принимает загрузки во временные приватные файлы, без полной буферизации в памяти. Максимум файла 512 МиБ, одновременно не более двух загрузок; при занятости возвращается 503 с `Retry-After: 5`. Медленная загрузка не удерживает блокировку черновика. HTTP обслуживается ограниченным пулом потоков. Для внешнего доступа по-прежнему нужен HTTPS-прокси с лимитами соединений, размеров тела и времени чтения, а также достаточное свободное место на диске.

Control ограничивает ожидание чтения 15 секундами, изменения 60 секундами, загрузки файла 5 минутами. Тайм-аут или потеря ответа не отменяет уже выполняющуюся операцию сервера. Перед повтором изменения получите актуальное состояние; автоматические повторы не выполняются.

### Остальные публичные адреса

- `GET /` — `{ service, role }`: что это за сервис (`udmc-sync-fabric` или `udmc-sync-neoforge`).
- `GET /udmc` и `GET /agents/install` — одна и та же HTML-страница для игрока: что установить и откуда скачать. Короткий адрес игрок перепечатывает с экрана отказа, где ссылку нельзя нажать.
- `GET /agents/info` — `{ packName, gameAddress }`: как называется сборка и куда заходить.
- `GET /agents/client` — описание файла, который сервер раздаёт игрокам (версия, хеш, номер выпуска); 404 `CLIENT_AGENT_NOT_READY`, пока сервер его не издал.
- `GET /agents/download` и `GET /agents/files/<имя>` — сам файл: ссылка для игроков и её вариант с именем файла.

## Admin API

### Устройства и приглашения

Все ключи передаются только в заголовках или JSON-теле по HTTPS, не в URL. Ответы доступа не кэшируются. Описание сценария: [administrators.md](administrators.md).

| Метод и путь | Доступ | Тело / результат |
| --- | --- | --- |
| `POST /access/request` | Одноразовое приглашение | `{ invite, token, name }`, где `token` - новый ключ устройства из 32 случайных байт в hex. Ответ 202 с ID, кодом проверки и статусом `pending`; поле `role` клиента не определяет права. |
| `GET /access/status` | Ключ устройства | Только собственная заявка/статус, не доступ к admin API. |
| `POST /access/cancel` | Ключ ожидающего устройства | Отменяет свою заявку. |
| `GET /admin/access/me` | Подтверждённый ключ или ключ восстановления | Собственный ID, роль, признак `bootstrap`, количество ожидающих заявок для владельца. |
| `POST /admin/access/owner` | Только главный ключ восстановления | `{ token, name }`, регистрация владельческого устройства; повтор того же запроса идемпотентен. |
| `GET /admin/access` | Владелец | Устройства, действующие приглашения и последние события; без ключей и их хешей. |
| `POST /admin/access/invitations` | Владелец | Ответ 201 с одноразовым `code` и сроком действия. |
| `POST /admin/access/invitations/revoke` | Владелец | `{ id }`. |
| `POST /admin/access/decision` | Владелец | `{ id, action }`, действие `approve`, `reject` или `revoke`. Самоотзыв запрещён. |

Приглашение действительно 15 минут, ожидающая заявка 30 минут. Повтор запроса с тем же приглашением и ключом возвращает ту же заявку, но не создаёт новую. Клиент самостоятельно сверяет короткий код с владельцем перед подтверждением. Для решения владелец должен авторизовать запрос; одно знание ID или кода проверки прав не даёт.

Роль `admin` допускает обычные операции сборки/сервера, но не управление доступом. Неизвестные, ожидающие и отозванные ключи получают 401; недостаточная роль 403; конфликт состояния 409; превышение лимита заявок/неудачной авторизации с IP 429. Отозванный ключ может проверить собственный статус через `/access/status`, но не изменять сервер. `/admin/status` включает `access` с собственными правами.

### Каталог команд и серверные файлы

- `GET /admin/server/commands`: `{ source, minecraftVersion, commands: [{ name, usage: string[] }] }`. Получает доступные команды из Brigadier-диспетчера в основном потоке сервера. Требует запущенный Minecraft, иначе 503.
- `GET /admin/server/files`: `{ files: [{ path, size, sha256, removalPending, modIds, modVersion }], truncated }`. До 1000 неуправляемых файлов, глубина обхода до 12, только разрешённые корни, без ссылок, UDMC-конфигов и JAR агента. У jar-файлов названы id и версия модов — так панель узнаёт копию того же мода под другим именем.
- `POST /admin/server/files/import`: `{ path, side, sha256 }`. Проверяет, что файл не изменился после сканирования, затем добавляет его в черновик. Применение и начало управления требуют публикации. Файлы клиента напрямую не просматриваются.
- `POST /admin/server/files/remove`: `{ path, sha256 }`. Помечает файл вне сборки к удалению с сервера при следующей публикации (с резервной копией); повторный вызов снимает пометку. Отвечает состоянием черновика.
- `POST /admin/files/detach`: `{ path }`. Снимает серверный файл с управления: он остаётся на диске, но из сборки уходит. Только для файлов со стороной `server` — 409 `DETACH_SERVER_SIDE_ONLY`.

В `/admin/status` добавлен `security.signedManifest`. Это состояние подписи на сервере, не доказательство HTTPS на участке между панелью и прокси.

Admin-запросы требуют один из заголовков:

```text
x-udmc-token: <token>
Authorization: Bearer <token>
```

### Рабочее пространство

Черновик правит одна панель за раз. Каждый изменяющий запрос несёт `x-udmc-session` (случайная строка 16–80 символов, одна на окно панели) и `x-udmc-revision` — ревизию состояния, которое панель видела. Ответы `GET /admin/files`, `/admin/agents` и `/admin/validation` возвращают текущую ревизию в заголовке `x-udmc-revision`. Ошибки: 428 `WORKSPACE_REQUIRED` — нет сессии или ревизии (старая панель); 409 `WORKSPACE_STALE` — сервер изменился, обновите состав; 423 `WORKSPACE_LOCKED` — редактирует другая панель, в ответе её имя. Аренду продлевает `POST /admin/workspace/heartbeat`, отпускает `POST /admin/workspace/release`, кто сейчас в панели — `GET /admin/workspace`.

### Агенты и проверка

- `GET /admin/agents`: что сервер раздаёт игрокам и в каком состоянии обновление — версия и файл клиента, `requireClient`, `gameAddress`, `serverUrl`, ссылка для игроков, `update.state`, `canUpdate`.
- `POST /admin/agents/update`: тело — ZIP с `client.jar` и `server.jar` из Control одной версии; 202, обновление применяется после выхода сервера (на Linux — сразу, вступает в силу при следующем запуске). Одна загрузка за раз: 503 `UPLOAD_BUSY`.
- `POST /admin/agents/client`: тело — JAR, который сервер должен раздавать игрокам вместо своего; 201. Обычно не нужен: сервер издаёт свой собственный файл сам.
- `GET /admin/validation?target=draft|server`: проверка состава — `{ ok, issues: [{ side, level, code, args, message }], checkedAt }`. `level` — `error` или `warning`; публикацию отклоняют только ошибки.

### `GET /admin/files`

Возвращает состояние редактирования:

- `published`: опубликованный manifest;
- `revision`: непрозрачная ревизия текущего состояния; каждый изменяющий запрос передаёт её в заголовке `x-udmc-revision` вместе с `x-udmc-session` (см. «Рабочее пространство»). При отличии агент отвечает 409 без изменений; проверка и применение выполняются под общей блокировкой хранилища;
- `draft`: manifest черновика; `draft` и `published` несут также `serverRemovals` (файлы вне сборки, помеченные к удалению) и `detached` (снятые с управления);
- `files`: объединённый список строк с полем `change`: `added`, `updated`, `removed`, `unchanged`. Строка несёт `path`, `side`, `sha256`, `size`, `modIds`, `modVersion`, `source` (откуда файл взят из каталога: `provider`, `projectId`, `versionId`) и флаги `serverRemoval`, `detached`;
- `changes`: счётчики `added`, `updated`, `removed`, `total`, флаг `dirty` и `serverRestartRecommended`.

Строка `removed` отсутствует в `draft.files`, но сохраняется в `files` для отображения и отмены удаления.

### `GET /admin/status`

Возвращает состояние Minecraft-сервера, игроков, uptime, TPS, среднее время тика, память JVM, количество миров, версию Java, состояние RCON и доступные действия.

### `POST /admin/files`

Тело запроса содержит сырой файл.

Создаёт или заменяет файл **только в черновике**. Серверные каталоги и публичный manifest не изменяются. Максимум 512 МиБ на файл.

```text
x-udmc-path: mods/SomeMod.jar
x-udmc-side: both
content-type: application/octet-stream
```

Вместо `x-udmc-path` можно передать URL-параметр `path`, например `POST /admin/files?path=mods%2FSomeMod.jar`. Для кириллицы и других символов вне ASCII используйте URL-параметр с percent-encoding.

Параметр `replace=<путь в черновике>` ставит новый файл на место старого одной операцией — так каталог и ручная загрузка заменяют прежнюю версию мода, и никто не видит черновик с двумя копиями. Заголовок `x-udmc-source` (JSON до 1024 байт: `provider`, `projectId`, `versionId`) запоминает, откуда файл взят; иначе 400 `CATALOG_SOURCE_TOO_LARGE` или `CATALOG_SOURCE_INVALID`. Ответ 201 `{ file }` со строкой черновика.

Допустимые корни: `mods/`, `config/`, `resourcepacks/`, `shaderpacks/`.

Допустимые стороны: `client`, `server`, `both`.

### `DELETE /admin/files?path=mods/SomeMod.jar`

Удаляет запись из черновика. Публичная сборка и серверный файл остаются без изменений до публикации. Blob остаётся в хранилище.

### `POST /admin/files/update`

```json
{
  "path": "config/settings.json",
  "newPath": "config/nested/settings.json",
  "side": "client"
}
```

Меняет путь и назначение уже загруженного файла без повторной отправки содержимого. `newPath` можно опустить. Занятый путь не перезаписывается; пути, отличающиеся только регистром, считаются конфликтом для совместимости с Windows.

### `POST /admin/files/revert`

```json
{ "path": "mods/SomeMod.jar" }
```

Возвращает файл к опубликованной записи. Если он не публиковался, удаляет новое добавление из черновика. Возвращает состояние как `GET /admin/files`.

### `POST /admin/draft/reset`

Заменяет весь черновик опубликованным manifest. Возвращает обновлённое состояние редактирования.

### `POST /admin/publish`

```json
{
  "version": "0.1.1"
}
```

Если `version` не передан, patch-часть увеличивается автоматически. Пустой неизменённый черновик публиковать нельзя.

Агент проверяет blobs по SHA-256, сохраняет временные копии затрагиваемых серверных файлов, применяет разницу и записывает опубликованный manifest. Черновик становится копией нового релиза. При обрабатываемой ошибке записи выполняется попытка отката. При удалении серверный файл сохраняется, если он был локально изменён. Изменение работающего Minecraft-процесса требует перезапуска.

### `GET /admin/project/backup`

Только владелец. Отдаёт проект целиком, включая закрытый ключ подписи: `{ format, packId,
packName, adminToken, manifestPublicKey, manifestPrivateKey, fingerprint }`.

Это единственное обращение, которое кладёт ключ подписи в сеть, поэтому оно отдельное и
осознанное, а не часть привязки. Полученный файл восстанавливает проект на новом сервере через
`POST /pair` с полем `project`.

### `POST /admin/agents/settings`

Принимает `{ requireClient }`, `{ gameAddress }` и `{ serverUrl }` — по отдельности или вместе.

`serverUrl` — адрес, по которому игроки берут сборку; сервер называет его клиенту при входе.
Сам себя снаружи сервер не видит, поэтому адрес приходит от панели: тот, которым она до него
дозвонилась. Принимаются только `http` и `https` без учётных данных, параметров и якоря.

### `POST /admin/settings`

```json
{
  "packName": "Main Server Pack"
}
```

Версии Minecraft и загрузчика не принимаются от панели: серверный агент определяет их автоматически.

### `POST /admin/server/command`

```json
{
  "command": "list"
}
```

Команда выполняется с правами серверной консоли. Начальный `/` необязателен. Переносы строк запрещены, максимальная длина — 512 символов.

### `POST /admin/server/restart`

Создаёт `udmc-sync/restart-requested` и корректно останавливает сервер. Повторный запуск выполняет UDMC wrapper или внешний supervisor. Доступно на выделенном сервере: `capabilities.powerActions` в `/admin/status` говорит, умеет ли этот процесс останавливаться.

Тело необязательно: `{ delaySeconds }` (0–600) откладывает остановку и предупреждает игроков в чате, `{ cancel: true }` отменяет отложенную. Ответ 202 `{ accepted, action }`; 400 `POWER_DELAY_INVALID`, 503 `MINECRAFT_NOT_READY`.

### `POST /admin/server/stop`

Удаляет маркер перезапуска и корректно останавливает сервер. Отдельного разрешения не требует: администратор, дошедший до этого запроса, может набрать `stop` в консоли того же API. Тело и ответы те же, что у перезапуска.

## Коды ошибок

Ошибка приходит как `{ error: { code, message } }`; панель переводит код, а `message` — английское пояснение для журнала. Статус в таблице — HTTP-ответ.

| Код | Статус | Значение |
| --- | --- | --- |
| `ACCESS_ACTION_INVALID` | 400 | неизвестное действие с доступом |
| `ACCESS_ALREADY_REVOKED` | 409 | доступ уже отозван |
| `ACCESS_DECISION_BODY_REQUIRED`, `ACCESS_DEVICE_BODY_REQUIRED`, `ACCESS_INVITATION_BODY_REQUIRED`, `ACCESS_REQUEST_BODY_REQUIRED` | 400 | в теле нет обязательных полей |
| `ACCESS_DEVICE_KEY_INVALID` | 400 | ключ устройства — не 32 случайных байта в hex |
| `ACCESS_DEVICE_KEY_USED` | 409 | такой ключ устройства уже зарегистрирован |
| `ACCESS_DEVICE_LIMIT` | 409 | сто устройств; сначала отзовите ненужные |
| `ACCESS_DEVICE_NAME_INVALID` | 400 | имя устройства: 1–64 символа без управляющих |
| `ACCESS_DEVICE_NOT_APPROVED` | 401 | устройство не подтверждено или отозвано |
| `ACCESS_DEVICE_NOT_FOUND` | 401 | устройство неизвестно; нужно новое приглашение |
| `ACCESS_INVITE_INVALID` | 403 | приглашение недействительно, использовано или истекло |
| `ACCESS_INVITE_LIMIT` | 409 | уже десять действующих приглашений |
| `ACCESS_INVITE_NOT_FOUND` | 404 | приглашение не найдено |
| `ACCESS_OWNER_REQUIRED` | 403 | только владелец: устройства, приглашения, резервная копия |
| `ACCESS_RATE_LIMIT` | 429 | слишком много попыток с одного адреса, подождите минуту |
| `ACCESS_RECOVERY_KEY_REQUIRED` | 403 | восстановление владельца требует ключ восстановления проекта |
| `ACCESS_REQUEST_LIMIT` | 429 | слишком много ожидающих заявок; владелец должен их разобрать |
| `ACCESS_REQUEST_NOT_FOUND`, `ACCESS_REQUEST_NOT_PENDING`, `ACCESS_REQUEST_RESOLVED` | 404 / 409 | заявка не найдена, уже решена или истекла |
| `ACCESS_SELF_REVOKE` | 409 | своё текущее устройство отсюда не отзывают |
| `ACCESS_SEPARATE_DEVICE_KEY_REQUIRED` | 400 | ключ восстановления нельзя использовать как ключ устройства |
| `AGENT_ARCHIVE_INVALID`, `AGENT_ARCHIVE_TOO_LARGE`, `AGENT_JAR_SIZE_INVALID` | 400 | загруженный JAR агента повреждён или слишком велик |
| `AGENT_BUNDLE_INVALID`, `AGENT_BUNDLE_VERSION_MISMATCH` | 400 | ожидался ZIP с `client.jar` и `server.jar` одной версии |
| `AGENT_DOWNGRADE_FORBIDDEN` | 409 | старая панель не может понизить версию агента |
| `AGENT_METADATA_INVALID`, `AGENT_VERSION_INVALID` | 400 | метаданные или версия агента не читаются |
| `AGENT_NOT_UPDATE_CAPABLE` | 400 | это не агент UDMC, умеющий обновляться |
| `AGENT_PLATFORM_MISMATCH` | 400 | агент для другой версии Minecraft или загрузчика |

## Manifest

### Проверка модов

Готовый Minecraft-сервер объявляет `capabilities.modValidation: true` в `/admin/status`; Control использует этот флаг перед импортом из каталога.

`POST /admin/publish` дополнительно проверяет Fabric JAR: метаданные, назначение, дубликаты ID, обязательные зависимости и `breaks`, включая вложенные моды. Проверка выполняется до изменения серверных файлов. Также учитываются оставшиеся личные моды сервера. Неуправляемый или локально изменённый серверный файл с другим содержимым не перезаписывается публикацией. При ошибке черновик остаётся доступен для исправления, а публикация не происходит.

С 0.3.0 NeoForge-агент использует тот же API и проверяет `META-INF/neoforge.mods.toml`, Maven ranges, FML, стороны и типы зависимостей, порядок загрузки и Jar-in-Jar. Неизвестные языковые загрузчики и неоднозначные встроенные версии отклоняются. `/health.service` возвращает `udmc-sync-neoforge`, `/admin/status.loader.type` и `manifest.minecraft.loader.type` содержат `neoforge`. Подписанный manifest другого загрузчика отклоняется клиентом до записи файлов, даже при совпадении номера Minecraft.

Каталог Modrinth вызывается нативными командами Control, не новым публичным маршрутом агента. Токен UDMC не отправляется Modrinth. Импорт использует существующий `/admin/files` и не вызывает `/admin/publish` автоматически.

Форма manifest определена классами `ManifestModels` в `minecraft/udmc-sync-common`; пример ниже.

```json
{
  "schemaVersion": 1,
  "pack": {
    "id": "main",
    "name": "Main Server Pack",
    "version": "0.1.1"
  },
  "minecraft": {
    "version": "26.2",
    "loader": {
      "type": "fabric",
      "version": "0.19.3"
    }
  },
  "publishedAt": "2026-08-26T00:00:00Z",
  "files": []
}
```
