# Частые вопросы

## Ключи случайные? У каждого игрока свой токен?

Административный токен содержит 32 случайных байта (256 бит). Пара Ed25519 и токен создаются системным криптографическим генератором. Совпадение независимо созданных ключей практически невероятно, но математически нулевую вероятность обещать нельзя.

Ключи подписи и главный ключ относятся к проекту, не к каждому игроку. На одном компьютере, в одной учётной записи Windows, одинаковый ID проекта намеренно загружает прежние ключи. Для отдельного проекта используйте другой ID. При переносе владельца на другую машину восстановите ключи из приватного серверного JAR. Для друга используйте приглашение, не передавайте серверный JAR: каждый компьютер получает отдельный случайный ключ доступа с возможностью отзыва. [Несколько администраторов](administrators.md).

Игроки получают общий публичный ключ проверки подписи, не токен администратора. Публичный ключ не является секретом. Файлы сборки публичны по URL; отдельной авторизации каждого скачивающего игрока сейчас нет. HTTPS шифрует передачу, Ed25519 и SHA-256 проверяют подлинность и целостность.

## Можно установить первый агент кнопкой внутри обычного Minecraft?

Без уже установленного клиентского кода сервер не может записать JAR в папку `mods`, добавить исполняемый мод или открыть собственный установщик внутри игры. Загрузка серверного ресурспака не предоставляет права устанавливать код.

Безопасные варианты: один раз положить готовый клиентский JAR в профиль Fabric или NeoForge; использовать функцию установки сборки существующего игрового лаунчера; либо в будущем сделать отдельный установщик с явным выбором профиля. Последние два варианта не реализованы в UDMC и не означают, что сервер может сам установить агент.

В этой версии ещё нет проверки присутствия агента при входе на сервер или кнопки скачивания на экране отказа. Не рассчитывайте на них при выдаче JAR игрокам. Уже установленный агент знает папку игры через загрузчик и показывает синхронизацию, конфликты и предложение перезапуска в самой игре.

## Почему нельзя оставить любой мод с такой же версией?

Два разных JAR могут объявлять одинаковую версию, но содержать другой код. Поэтому автоматически переиспользуется только файл с точным SHA-256 из подписанной сборки. Другой JAR с тем же ID требует решения пользователя. UDMC не может доказать, что произвольная более новая версия совместима с сервером.

Перед публикацией проверяются объявленные зависимости и `breaks`, но не поведение кода модов. Удаление мода с блоками или измерениями может повредить мир даже при корректных метаданных. Сохраняйте резервные копии.

## Какой адрес вводить?

- `sync.example.com`: HTTPS через уже настроенный прокси, стандартный внешний порт 443.
- `https://sync.example.com:8443`: HTTPS на нестандартном внешнем порту, внутренний порт UDMC по умолчанию 3077.
- `192.168.1.50:3077` или `sync.example.com:3077`: прямой HTTP, только для доверенной сети с явным разрешением.
- **На этом ПК**: подключение админ-панели к локальному агенту. Для других игроков нужен доступный им адрес, не localhost.

Порт входа в Minecraft и порт RCON не являются портами UDMC. Папку установленного Minecraft панель не ищет: агент запускается загрузчиком в правильном профиле. Для сервера дома настройка сети зависит от роутера, провайдера, VPN и хостинга; приложение не может автоматически устранить CGNAT.

## Нужно регистрироваться в Modrinth?

Для публичного каталога и скачивания модов нет. API поддерживает авторизацию для приватных данных и действий аккаунта, но UDMC сейчас ими не пользуется. Это первый этап интеграции: поиск модов и подбор обязательных зависимостей, без миров, готовых модпаков, личных коллекций и фонового автообновления. [Документация Modrinth](https://docs.modrinth.com/api/).

При открытии каталога сразу загружаются популярные моды. Minecraft-клиент не нужен. Даже без подключения к серверному агенту можно выбрать версию игры, искать и просматривать зависимости. Для добавления в общий черновик требуется доступ к обновлённому серверному агенту.

## Зачем имя сборки, ID и два порта?

Название на странице **Сборка** предназначено людям, его можно менять. Постоянный ID в генераторе связывает проект, его ключи и локальное состояние агентов; менять его при обычном обновлении не нужно. Генератор использует то же название, отдельного поля имени больше нет.

Адрес вводится один раз в **Агент и доступ**. При прямом `IP:порт` этот порт используется и агентом. За HTTPS-прокси или NAT внешний порт может отличаться от внутреннего: например, `443` снаружи и `3077` внутри. Поле внутреннего порта видно только при явном выборе такого отличия. Прослушивание на сервере определяет доступ снаружи или только локально, а не адрес игроков.

## Почему ID, адрес и некоторые другие поля нельзя просто напечатать?

Это защита от случайного изменения. Нажмите карандаш рядом с полем или заголовком раздела. Измените значения в открывшемся окне, прочитайте предупреждение и нажмите **Применить**. **Отмена** или Escape сохраняют прежние значения. После перезапуска поля также остаются заблокированными.

Обычный ID `udmc-main` менять не нужно. Для другого проекта есть отдельное подтверждение: другой ID выбирает другие ключи, уже выданные JAR не переключатся на него. Чтобы просто переименовать сборку, измените название на странице **Сборка**. Блокировка ввода не заменяет авторизацию, защиту Windows и резервные копии.

## Как меняется версия приложения?

Обычный выпуск повышает последнее число: `0.2.0 → 0.2.1 → 0.2.2`. Переход на `0.3.0` делается отдельно при minor-выпуске. Номер приложения, номер агента и номер опубликованной сборки модов не следует путать: версия сборки модов меняется при публикации.

Новый установщик получает новую версию автоматически в процессе выпуска. Автоматическое скачивание и установка новой версии уже установленным UDMC Control пока не реализованы.

Начиная с установщика 0.2.2 обновление существующей NSIS-установки выполняется поверх прежних файлов в одном мастере, без отдельного деинсталлятора. Закройте Control перед обновлением. Сохранённые настройки и ключи остаются на месте.
