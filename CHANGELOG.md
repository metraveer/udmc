# Изменения

## 0.19.0 - 2026-08-31

- Проверка клиента при входе переехала из фазы входа в фазу подключения. Прежний способ жил на канале, который Fabric API забирает себе целиком, поэтому на реальных сборках исход решал случайный порядок применения модов: сервер объявлял исправно установленный клиент отсутствующим, а если Fabric API стоял ещё и на сервере - вход вешался до таймаута. Теперь UDMC ничего не отменяет и ни с кем не соревнуется: вопрос идёт по собственному каналу там, где это предусмотрено самой игрой.
- На NeoForge проверка использует его собственный механизм регистрации вместо миксинов - там незарегистрированный пакет означает отключение с чужой формулировкой.
- Обновление сервера один раз выключает правило «вход только с клиентским UDMC». Клиенты прежних версий не умеют отвечать на новый вопрос, и без этого сервер закрылся бы для всех своих игроков в момент обновления. Раздайте новый клиентский JAR и включите правило обратно.
- Сообщение об отсутствующем клиенте на время перехода учитывает и вторую причину: клиент может быть установлен, но остаться от прежней версии - тогда достаточно один раз перезапустить игру.
- В стенде сквозной проверки записана матрица из шести расстановок Fabric API; проверка проходит все шесть, включая ту, на которой ломался прежний способ, и ту, которую он не ломал.

**В этом выпуске меняются агенты.** Обновите их кнопкой «Обновить и перезапустить», затем раздайте игрокам новый клиентский JAR и снова включите «Вход только с клиентским UDMC».

## 0.18.0 - 2026-08-30

- Сервер больше не пишет «синхронизатор не установлен», когда мод установлен. Клиент другого проекта раньше молчал в ответ на проверку, и сервер объявлял мод отсутствующим - это единственное, чего он знать не мог. Теперь такой клиент отвечает и называет свой проект, а сервер пишет по делу: «клиент установлен, но настроен на другой проект; этому серверу нужен «имя»».
- На экране отказа появились версии: какой агент работает на сервере, какой клиент он раздаёт, какой проект ему нужен и какая версия у игрока. Раньше сверить это было нечем.
- Устаревший клиент теперь называет обе версии: «сервер раздаёт 0.17.1, а у вас 0.17.0».
- Страница установки показывает версию клиентского агента и ID проекта рядом с названием сборки.
- Новый клиентский JAR теперь действительно перенимает настройки на себя. Раньше конфиг, оставшийся от другого проекта, переживал замену мода: клиент продолжал отвечать за прежний проект, а сервер мог сообщить об этом только как о неустановленном моде. Теперь установленный файл задаёт проект, а прежние настройки сохраняются рядом в `udmc-sync-previous.json`. Серверный JAR по-прежнему отказывается перезаписывать чужой проект: там лежат ключи.
- JAR, собранный из исходников, больше не притворяется рабочим клиентом. Он не несёт настроек сервера, и раньше молча продолжал жить со старым конфигом; теперь игра сразу говорит, что этот файл ни к какому серверу не привязан и клиент нужно скачать со страницы установки.
- На экране отказа рядом со строкой сервера стоит строка клиента: его версия и его проект. Две строки под одной, чтобы расхождение было видно сразу.
- «Устарел» больше не пишется там, где версии совпадают. Пересобранный клиентский JAR (сменился адрес, имя сборки, сеть) сохраняет версию агента, и прежнее сообщение выглядело как «сервер раздаёт 0.17.1, а у вас 0.17.1». Теперь это отдельная причина: «версия та же, но сборка другая».
- Пока на сервере не опубликован клиентский агент, сравнивать не с чем - и сервер больше не объявляет исправный клиент устаревшим против версии, которую сам не может назвать.
- Игроку без мода первая строка отказа теперь приходит на двух языках: своих переводов у него нет, а именно эту строку он и читает первой.
- Экран отказа больше не отправляет качать файл там, где клиент чинит себя сам. Клиент сверяет свой JAR с опубликованным при каждом запуске игры и заменяет его: если файл просто устарел или пересобран, единственное нужное действие - перезапустить игру. Совет «скачайте и положите в mods» остался там, где рабочего канала ещё нет: мода нет вовсе или он от другого проекта и не может проверить подпись этого сервера.

**В этом выпуске меняются агенты.** Обновите их кнопкой «Обновить и перезапустить». Клиентов раздавать заново не нужно: после обновления серверного агента игроки получат новый клиент сами при следующем запуске игры - клиент сверяет свой файл с опубликованным и заменяет его. Руками файл ставится только тому, у кого мода нет вовсе или он остался от другого проекта.

## 0.17.1 - 2026-08-30

- Игра больше не падает при первом запуске после установки нового клиентского JAR. Клиент читал `config/udmc-sync.json` и тут же переписывал его, не отпустив файл, а Windows не даёт заменить файл с открытым дескриптором - запуск обрывался ошибкой «Cannot save UDMC config». Ошибка давняя: она срабатывала при каждой смене версии клиентского агента, то есть у каждого игрока после раздачи обновлённого клиента. На Linux этого не было, поэтому серверы не задевало.

**В этом выпуске меняются агенты.** Обновите их кнопкой «Обновить и перезапустить» и раздайте игрокам новый клиентский JAR. Если игра уже не запускается, удалите у себя `config/udmc-sync.json` в папке профиля - клиент создаст его заново из JAR.

## 0.14.0 - 2026-08-30

## 0.10.0 - 2026-08-30

- Обновление агентов починено для хостингов и панелей, которые жёстко завершают процессы. На Linux серверный JAR теперь заменяется сразу на месте (работающий сервер спокойно доживает на старой копии, новый файл подхватывается при следующем запуске) - внешний процесс-помощник, которого раньше убивал хостинг, больше не нужен. Windows-клиенты игроков продолжают использовать прежний механизм замены после выхода игры.
- Зависшее «обновление не завершилось» самоизлечивается: если установленный агент уже той версии, на которую готовилось обновление (доехало помощником, заменой на месте или руками) - статус становится «применено», ложная тревога исчезает. В подсказке о сбое появился запасной путь: ручная замена JAR через «Создать JAR» с сохранением ключей.
- Назначение и папку уже опубликованных файлов снова можно менять: списки на «Опубликовано» стали редактируемыми - изменение помечает строку «Изменён» и попадает в черновик, применяясь при публикации, как и всё остальное.
- На «Вне сборки» дописано, как передумать: пока не опубликовано, «Отменить изменение» на вкладке «Черновик» возвращает взятый под управление файл обратно; назначение «Только сервер» игрокам не раздаётся.

**В этом выпуске меняются агенты** (новый механизм замены). Обновите агентов после установки; если прежние попытки застревали на «не завершилось» - на Linux-хостинге это обновление станет последним, которое придётся делать руками: скачайте серверный JAR через «Создать JAR» (ключи сохранятся), остановите сервер, замените файл, запустите.
