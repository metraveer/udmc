# Безопасность

## Поддерживаемые версии

До первого стабильного релиза исправления безопасности выпускаются только для текущей ветки разработки.

## Сообщение об уязвимости

Не публикуйте рабочий exploit, токен или данные сервера в открытом issue. Используйте private vulnerability report в разделе **Security** GitHub-репозитория. Если private reporting ещё не включён, создайте issue без чувствительных деталей и попросите приватный канал связи.

## Модель угроз preview-версии

- `/manifest` и `/files/*` публичны по дизайну;
- черновик не виден в публичном manifest, но blob можно скачать, зная его URL; это не приватное файловое хранилище;
- `/admin/*` проверяет отдельный ключ устройства; приглашения требуют подтверждения владельцем, ожидающие и отозванные устройства к admin API не допускаются;
- главный токен проекта остаётся владельческим ключом восстановления: его обладатель может зарегистрировать нового владельца, поэтому он не передаётся другим администраторам;
- сервер хранит SHA-256 случайных 256-битных ключей/приглашений в атомарно сохраняемом реестре, привязанном к ключам проекта; приглашения одноразовые с TTL 15 минут, заявки с TTL 30 минут;
- встроенный HTTP API не шифрует трафик;
- UDMC Control хранит адрес в WebView storage, ключи проектов и токены в Windows Credential Manager;
- пароль RCON сохраняется в Windows Credential Manager сразу и отдельно для каждого сервера в панели; стёртый в редакторе пароль удаляется оттуда же;
- RCON передаёт пароль и команды без TLS;
- командный API и управление питанием обладают правами серверной консоли;
- загруженный серверный файл записывается только в разрешённые корни `gameDir`;
- серверные файлы применяются только при публикации; конфигурацию доступа `config/udmc-sync.json` нельзя включать в сборку;
- клиент проверяет SHA-256 каждого скачанного файла;
- клиент проверяет Ed25519-подпись точных UTF-8 байтов manifest до разбора JSON и изменения файлов;
- клиент закрепляет публичный ключ проекта и отклоняет меньший `releaseSequence`, чем ранее принятый;
- SHA-256 файлов связан с подписанным manifest: подменить файл, не подменив подписанный manifest, нельзя;
- все клиентские загрузки проверяются до изменения управляемых файлов; ошибка записи вызывает попытку восстановления;
- личные или изменённые файлы не перезаписываются клиентом; изменённый локально файл не удаляется;
- идентичные личные файлы помечаются `borrowed` и не удаляются следующими публикациями;
- отключение конфликтующего файла требует подтверждения конкретного имени; перед удалением повторно проверяется SHA-256 и создаётся копия в `udmc-sync/backups`;
- перед публикацией проверяются метаданные Fabric или NeoForge и объявленные зависимости, но это не песочница и не антивирус;
- Modrinth использует отдельные HTTPS-запросы без административных секретов UDMC; загрузка ограничена официальным CDN, без перенаправлений, с размером и SHA-512;
- файл мода один для сервера и для игроков и не содержит ни ключей, ни адресов. Секреты живут в `config/udmc-sync.json` на самом сервере — вот его отдавать нельзя;
- подпись подтверждает ключ сервера, но не безопасность самого мода и не защищает от владельца украденного admin-токена;
- файл мода игрок должен брать по ссылке сервера или у владельца: подменённый мод закрепит чужой ключ при первом входе.

## Рекомендации

- ключ доступа сервер создаёт сам при первом запуске; если в конфиге всё же стоит `change-me` (файл писали руками), замените его случайным значением не короче 32 байт до открытия API;
- передавайте Admin API только через HTTPS, VPN или SSH-туннель;
- ограничьте `/admin/*` и `/access/*` по IP на reverse proxy, разрешив адреса приглашённых администраторов;
- не публикуйте RCON-порт в интернет; используйте firewall, VPN или SSH-туннель;
- давайте доступ к панели только тем, кому доверяете консоль сервера: остановка и перезапуск отдельного разрешения не требуют;
- не передавайте серверный `udmc-sync.json` игрокам;
- храните приватную резервную копию `config/udmc-sync.json` и не коммитьте её: в ней ключи проекта;
- делайте резервную копию серверной сборки перед крупным обновлением;
- распространяйте только те моды, лицензия которых разрешает такую раздачу;
- проверяйте Windows-инсталлятор и `.jar` по hash из доверенного релиза.

Кодовая подпись Windows пока не реализована. Подпись manifest реализована. HTTPS по-прежнему необходим для конфиденциальности и защиты ключей. Есть роли владельца и администратора, но нет тонкой настройки прав, автоматической ротации ключей или отзыва украденного клиентского JAR: клиентский ключ публичен, а содержимое сборки доступно по URL. Счётчик публикаций не гарантирует свежесть при первом запуске нового клиента и не защищает от отката всей локальной машины вместе с её состоянием.

Ошибки авторизации и заявки ограничены по IP (12 за минуту); это не общая защита API от DoS. Ограничьте размер, частоту и длительность запросов на reverse proxy. Журнал ограничен 250 событиями; IP за прокси и активность ключа не доказывают личность. Отзыв действует на новые запросы, не отменяет выполняющийся запрос и не заменяет ротацию украденного главного ключа. Подробности: [администраторы](docs/administrators.md).

Разрешённый администратор может публиковать исполняемые моды. Разделение ролей API не является песочницей для недоверенного серверного кода, и журнал на той же машине не защищён от администратора ОС. Подписи и временные резервные копии не заменяют постоянные резервные копии мира и тестирование модов.
